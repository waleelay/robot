本文档只记录从当前代码和部署配置可以确认的生产风险。它不是测试结果；“待整改”必须在上线评审中补充负责人、计划日期和证据链接。

## 1. 调用链路基线

```text
浏览器 --JWT--> BFF :8090
  -> Control :8082 --MQTT/TLS--> EMQX --> Go/Python 客户端或 Camera Gateway
  -> Media :8088 --> LiveKit / MinIO / MySQL
浏览器 --短期 viewer Token--> LiveKit
```

BFF 是浏览器唯一业务入口；Control 到 Media 的 `/internal/media/**` 是服务间入口；RTSP URL、publisher Token、Management Token 和 MQTT 凭据均属于敏感数据。

## 3. 各风险项详细整改边界

以下边界用于评审整改方案。除明确列出的范围外，不得借整改名义改变业务协议、设备控制语义或扩大网络暴露面。

### PROD-001：收敛 `/internal/media/**` 浏览器可达范围

**整改对象**：`bigscreen-bff` 的透明代理 Controller 和生产 Nginx 路由；Control 到 Media 的服务间地址、认证配置和内部接口 allowlist 本阶段不改。

**必须修改**：

1. **已完成**：BFF 不再注册或转发浏览器请求的 `/internal/media/**`；浏览器仍可使用已定义的 `/api/media/**` 公共接口，但只能访问接口文档列明的资源。
2. **已完成**：生产 Nginx 对 `/internal`、`/internal/**`、`/api-gw/internal` 和 `/api-gw/internal/**` 明确返回 `404`，同时阻断直接访问和 API Gateway 绕行。
3. **暂缓**：Control 到 Media 继续使用当前 `media-service.base-url` 直接调用 `/internal/media/**`，本阶段不增加 mTLS、服务 Token 或其他服务身份机制。
4. **暂缓**：本阶段不新增 Media 内部接口方法/路径 allowlist，保持现有 Controller 契约和服务间调用方式。

**明确不改**：不把 `/internal/media/**` 改名为新的浏览器接口；不把 Media 全部接口迁入 BFF；不让浏览器携带 Control/Media 服务凭据。

**本阶段完成条件**：BFF 直连 `/internal/media/**` 返回 `404` 且不调用代理客户端；生产 Nginx 的直接路径和 `/api-gw` 绕行路径均返回 `404`；Control 的内部 Media 客户端仍使用原 `/internal/media/**` 地址，相关测试通过。服务身份和访问日志区分属于第 3、4 项后续整改，不作为本阶段验收条件。

**与 Management Service 现状对照（2026-08-23）**：`eiop-management-service` 的内部接口统一使用 `/internal/v1/**`，其设计同样是服务间调用；现有 `ManagementAccessControlFilter` 只过滤 `/api/v1/management/**`，因此大多数内部 Controller（例如设备同步、固定摄像头媒体源、媒体绑定、控制记录同步）不经过用户权限过滤，安全边界由内网/网关隔离承担。只有 `InternalAccessAuthorizationController` 在方法内部显式校验 `Authorization` JWT，不能据此推断其他内部接口也有同等认证。这个实现并不表示内部接口设计错误，而是说明内部接口不能被 BFF 或公网透明暴露。

**本项不要求**：本次 BFF 整改不直接改 Management、Control、Media 的内部业务 Controller，不改变 `/internal/**` 契约，也不要求把所有内部接口改造成用户 JWT 接口。若需要在内网之外调用，应另立跨服务认证整改项，覆盖服务身份、密钥轮换和所有调用方。

### PROD-002：MQTT 和媒体敏感字段日志脱敏

**整改对象**：Control 的 MQTT 发布/订阅日志，以及生产部署的固定摄像头 Go Gateway 所使用的 `fixedcamera`、`publisher`、`rtsp` 日志链路。其他机器人 Go 客户端和 Python 客户端属于 Demo/模拟代码，不纳入本项敏感日志整改。

**字段边界**：`publisherToken`、`robotToken`、`accessToken`、`refreshToken`、`rtspUrl`（包括 URL 用户名密码）、`managementServiceToken`、MQTT 用户名/密码必须完整删除或统一显示 `[REDACTED]`。`sessionId`、`commandId`、`robotId`、`sourceType`、`sourceId`、`topic` 可保留。

**必须修改**：

1. **已完成**：Control 禁止打印完整 JSON payload；发布成功或 MQTT 禁用时只输出字段白名单摘要。
2. **已完成**：Control 订阅处理异常只记录中文事件描述、Topic 和载荷字节数，不记录原始 payload。
3. **已完成**：固定摄像头 Gateway 不记录 MQTT 原始载荷、MQTT Broker 地址、RTSP URL、LiveKit URL 或 Token；启动、停止、连接和失败日志均使用中文描述。
4. **已完成**：固定摄像头使用的 publisher 不记录外部命令参数，且不再把外部 GStreamer/FFmpeg 的 stdout/stderr 直接写入应用日志；`ffprobe` 成功输出也不再直接打印。
5. **已完成**：增加脱敏单测，覆盖视频启动、对讲启动、固定摄像头 RTSP/publisher Token 和控制命令参数。
6. **部署阶段执行**：对已有历史日志设置保留、删除和访问权限策略；脱敏只对新日志生效，不视为历史泄露已经自动消除。

**明确不改**：不降低 MQTT QoS；不改变 MQTT payload、Topic、状态码和业务调用顺序；不删除审计所需的 `sessionId/commandId/robotId/sourceId`；不整改 Demo Go/Python 客户端日志；不在前端增加 Token 日志。

**代码完成条件**：代码扫描不存在完整 payload 日志；Java 摘要不含 Token、LiveKit/RTSP URL、房间名和控制参数；固定摄像头 Go 日志不含 Token、RTSP 地址或摄像头地址；Control 与固定摄像头链路测试通过。生产完成条件还包括部署后日志采样和历史日志治理证据。

### PROD-003：收敛 Java 服务直连和可信 Header

**整改对象**：Nginx/Ingress、防火墙/安全组、BFF 到下游的 Header 注入、Control/Media 的安全配置。

**网络边界**：8082、8088 不对公网开放；8088 的机器人例外只允许已登记的上传网段和上传白名单路径，不能访问视频会话、删除文件或 `/internal/**`。

**身份边界**：BFF 必须覆盖客户端传入的 `X-User-Id`、`X-Org-Id`、`X-Roles` 等可信 Header；Control/Media 仅接受来自已认证 BFF/服务网段的这些 Header。直连请求不得通过伪造 Header 获得用户权限。

**明确不改**：不把 Header 当作设备身份认证；不允许通过扩大可信网段解决所有权限问题；不改变机器人现有 `X-Robot-Id` 上传协议。

**完成条件**：外部端口扫描不可达；直连伪造 Header 被拒绝；BFF 正常请求的用户、组织和角色上下文保持不变。

### PROD-004：MQTT 设备身份、ACL 与载荷一致性

**整改对象**：EMQX 用户/证书、Topic ACL、Control 订阅校验、Go/Python/Gateway 客户端连接配置。

**Topic 边界**：设备只能订阅自己的控制 Topic，只能发布自己的状态 Topic；Gateway 只能访问分配的 `gatewayId`。禁止使用所有设备通配符凭据作为生产默认配置。

**载荷边界**：服务端从 Topic 提取 `robotId`/`serialNumber`，与 payload 中同名字段不一致时拒绝并记录审计事件；不能通过 payload 覆盖 Topic 身份。

**必须具备**：TLS 或 MQTTS、设备级或站点级凭据、凭据轮换和吊销流程、ACL 变更审计。

**明确不改**：不新增第二套 Topic 命名；不允许为了兼容而放宽 ACL；不把客户端上报的用户身份作为设备认证。

### PROD-005：WebSocket 权限撤销窗口

**整改后实现（2026-08-23）**：

1. BFF 在 WebSocket 建连时使用当前 Token 分页查询 Management 的设备和固定摄像头；Management 明确返回 `401` 时以 `4001` 关闭，其他初始查询失败以 `4003` 关闭。前端会自动重连，但 `4003` 使用带随机抖动的指数退避，间隔从约 2 秒逐步增加到 30 秒并封顶，持续失败时显示“权限服务暂不可用”，不再固定每 2 秒无限请求。
2. BFF 按 `issuer + subject + orgId` 复用授权快照，快照记录 `loadedAt/expiresAt`。配置值和代码硬上限均为 30 秒；每 1 秒检查 Token/快照，在有效期过半后由独立线程按身份提前刷新，Management 慢请求不再串行阻塞其他会话。
3. 单次设备与固定摄像头完整权限加载设置 8 秒总时限，单个 HTTP 连接/读取超时仍为 2 秒/3 秒。
   后台刷新单次失败时保留尚未过期的快照并继续重试；到达快照硬过期时间仍未成功刷新时，
   不继续使用旧集合，以 `4003` 关闭该身份连接。JWT 自身到期必须以 `4001` 关闭，不能误报为
   权限服务故障。若 Management 已明确返回 `401`，即使 BFF 本机时钟因漂移尚未到 JWT `exp`，
   也必须以对端鉴权结果为准并按 `4001` 处理；业务代码不扩大 Token 时间容差。
4. 向浏览器下发设备事件前继续按 `robotId`、`cameraId` 或 `FIXED_CAMERA/sourceId` 过滤；无法识别资源的普通设备事件默认拒绝。用户范围任务、告警和统计事件仍由当前会话身份重新查询后发送。
5. WebSocket 保持双向。BFF 转发上行消息前检查 Token 和授权快照；消息显式携带无权 `robotId/cameraId` 时返回 `RESOURCE_FORBIDDEN`，不连接 Control/MQTT。没有资源 ID 的对讲查询等消息交由 Control 做最终鉴权。
6. Control 在发布 MQTT、签发/获取视频 Token 和执行对讲前继续按当前请求身份校验。机器人设备授权缓存默认 30 秒，且代码强制封顶 30 秒，即使环境变量误设更大也不会扩大撤权窗口；缓存过期查询失败时拒绝操作，不回退旧权限。
7. BFF 按握手 JWT `exp` 检查存量连接；Token 到期后停止收发并以 `4001` 关闭。前端收到 `4001` 后立即调用 Keycloak 刷新 Token，再建立唯一连接；刷新失败进入重新登录。
8. 权限刷新成功且资源集合变化时，BFF 更新集合并发送不含资源明细的
   `bigscreen.authorization.changed`。只有该确认事件允许前端先清空旧资源和失权播放，再通过
   当前 Token 重拉 Overview。普通 WebSocket 重连和固定摄像头健康变化只做非破坏性后台对账，
   不清空装备列表、不断开现有 LiveKit Room。单个资源失权不强制关闭仍拥有其他资源的连接。
   当前没有 Management 权限版本事件，提前主动失效仍是可选增强。

### PROD-006：固定摄像头配置状态与健康状态分离

**整改前事实与问题定位（2026-08-23）**：

1. `PanoramaService.fixedCameraDevice` 当前直接执行 `enabled=true -> status=online`、
   `enabled=false -> status=offline`；`deviceStats` 和 `deviceTypeStats` 又按该 `status` 统计，
   因而现状不只是字段文案不清，而是在线数量已经混入配置启停口径。
2. Gateway 当前只向 `gateway/fixed-camera/{gatewayId}/video/status` 上报
   `publishing/streaming/failed/stopped`。该消息以 `sessionId` 为主键，只说明某次视频会话，
   不能证明 Gateway 整体存活，也不能证明未被观看摄像头的 RTSP 可用。
3. Gateway 入口没有机器人心跳；Control 只把上述会话状态转交 Media 更新 `VideoSession`，
   没有固定摄像头健康状态仓库，BFF 也没有可合并的健康来源。
4. 前端地图弹窗已隐藏固定摄像头的部分在线标签，但 Overview 总数、在线/离线统计和部分
   “在线装备”筛选仍消费通用 `status`，仅隐藏文案不能消除错误口径。

**确认后的四类状态必须独立**：

| 状态维度 | 权威来源 | 建议状态 | 用途 |
| --- | --- | --- | --- |
| 配置启停 | Management `enabled` | `ENABLED/DISABLED` | 是否允许平台发起播放，不代表设备在线 |
| 配置完整性 | Management 协议和主/子码流 | `READY/INVALID` | 是否具备发起 RTSP 探测的必要配置，不代表 RTSP 可达 |
| Gateway 存活 | Gateway 独立 MQTT 心跳 | `ONLINE/OFFLINE/UNKNOWN` | 判断负责该摄像头的 Gateway 是否可接收命令 |
| 摄像头流健康 | Gateway 对目标 RTSP 的最近探测 | `AVAILABLE/UNAVAILABLE/UNKNOWN` | 判断最近一次 RTSP 探测结果；必须带检查时间和过期边界 |

`VideoSession.status` 的 `publishing/streaming/failed/stopped` 继续只描述一次播放会话，不能写回
上述四类设备状态，也不能作为未播放摄像头的健康依据。

**本项代码整改边界**：

1. Gateway 新增独立心跳 Topic `gateway/fixed-camera/{gatewayId}/status`，QoS 1，至少包含
   `gatewayId`、`status`、`reportedAt`、`reasonCode`、`version`；默认每 10 秒上报，Control
   连续 30 秒未收到新心跳即判为 `OFFLINE`。进程刚启动、Control 刚重启或数据过期时为
   `UNKNOWN`，不得乐观恢复成在线。心跳不得携带 Token、RTSP URL 或摄像头凭据。
2. Gateway 新增摄像头健康 Topic
   `gateway/fixed-camera/{gatewayId}/camera/{cameraId}/status`，至少包含 `gatewayId`、
   `cameraId`、`health`、`checkedAt`、`reasonCode`。Gateway 通过有并发上限的周期探测和
   start 前探测更新状态；建议探测周期 60 秒、状态最长有效 120 秒。超过有效期统一为
   `UNKNOWN`，不能永久沿用最后一次成功。错误原因必须使用枚举码，说明文本需限长且不得
   包含 RTSP URL。
3. Control 校验 Topic 中的 `gatewayId/cameraId` 与 payload 一致，只保存最新且序号/时间
   更新的状态，并对外提供按当前用户摄像头权限过滤的查询接口和 WebSocket 变化事件。
   本轮只要求最新短期状态，不建设健康历史报表。单实例可使用内存仓库；多实例部署前必须
   使用共享短期存储，或证明每个实例都能独立收到完整心跳和摄像头状态，禁止跨实例返回
   不一致的在线结果。
4. BFF 固定摄像头模型明确输出 `enabled`、`configStatus`、`gatewayHealth`、
   `streamHealth` 和各自时间。现有 `playable` 只能表示“配置允许发起播放”，应改名为
   `configReady`；完成调用方迁移后删除旧字段。通用 `status` 不再由 `enabled` 推导：
   仅当配置启用且完整、Gateway 心跳有效且最近 RTSP 探测成功时为 `online`；Gateway
   离线或有效期内的 RTSP 探测失败时为 `offline`；任一健康数据缺失/过期时为 `unknown`；
   配置停用时为 `disabled`。
5. `deviceStats` 与 `deviceTypeStats` 必须增加或明确 `unknown/disabled` 口径，且满足各状态
   数量可核对。前端固定摄像头展示“已启用/已停用”“Gateway 在线/离线/未知”“视频流
   可用/不可用/未知”，不得只显示一个“在线”。播放入口以 `enabled + configReady` 为配置
   门槛；Gateway 明确离线时可快速提示不可用，健康为 `UNKNOWN` 时允许发起一次真实探测，
   最终结果仍以该次 `VideoSession` 状态为准。
6. Gateway/摄像头健康变化通过现有 BFF WebSocket 连接按 `cameraId` 做用户资源过滤；事件
   只触发对应设备状态和统计刷新，不广播 RTSP 地址，也不要求前端轮询全量 Overview。

**整改中新增发现及处理**：

- 原 Gateway、Control 授权健康接口和 BFF 若固定只读第一页，超页摄像头会长期未知或缺失；
  现均已改为分页读取并设置最多 1000 页的安全上限，超限不得返回伪在线。
- 周期到达时前一轮 RTSP 探测可能尚未结束，直接重入会形成并发风暴；现已增加 single-flight
  和可配置并发上限，重叠轮次只记录中文跳过日志。
- Gateway 遗嘱与健康消息不使用 retained。Control 重启后状态短暂为 `UNKNOWN` 是失败安全设计，
  最迟由下一次心跳/探测恢复；不得为消除该窗口而恢复旧在线值。
- 新默认方案不向 Gateway 配置 Management Token。BFF 只在当前用户授权列表完整分页成功后续租；
  Management 故障、用户退出或租约同步失败会使目录在最长 300 秒内收口为空，摄像头保持

  资源标识；BFF 现已抑制原始事件，只发送不含资源明细的用户范围失效通知，并按当前身份

- Control 健康仓库当前为进程内存。单实例部署可用；多实例部署仍属于未关闭的生产边界，

1. `enabled=true` 但 Gateway 未启动时，接口和页面不得显示摄像头在线，在线统计不得增加。
2. Gateway 心跳中断后不超过 30 秒变为 `OFFLINE`；恢复后由新鲜心跳恢复，不能依赖旧消息。
3. RTSP 断开后在一次探测周期内变为 `UNAVAILABLE`，恢复并探测成功后变为 `AVAILABLE`；
   停止播放不会把摄像头判为离线。
4. 健康状态超过 120 秒未更新时变为 `UNKNOWN`，Control/BFF 重启期间不回退旧在线状态。
5. 固定摄像头的配置、Gateway、流健康和会话状态能够在接口、WebSocket、UI 和统计中逐项
   对账；任一日志和事件均不包含 RTSP URL、Token 或摄像头凭据。
6. 自动化测试至少覆盖启用但 Gateway 离线、Gateway 在线但 RTSP 不可达、状态过期、乱序
   消息、Topic/payload 身份不一致、恢复、Control 重启和多用户摄像头事件隔离。

### PROD-007：统计报告存储与多实例边界

**当前单实例允许**：本地磁盘生成、查询、下载和删除，但必须配置容量监控、清理失败告警和备份策略。

**多实例上线前必须**：报告 PDF 写入共享对象存储；索引写入共享数据库；下载、删除和 30 天/100 份清理使用统一存储接口并保证幂等；禁止依赖单节点 `data/` 目录。

**明确不改**：不把报告文件混入通用媒体文件权限模型；不允许用户通过 `id` 越权读取其他用户报告。

### PROD-008：里程质量、时区和缺失数据口径

**必须明确**：Control 以设备事件时间转换为 `Asia/Shanghai` 后入桶；首次读数只建基线；重复/乱序不计入；里程回退标记 `RESET` 或 `ESTIMATED`；速度异常标记 `SUSPECT`，不应作为正常里程汇总。

**整改边界**：对外统计至少返回数据范围、`hasData`、总米数和按机器人明细；如前端展示质量，必须区分 `NORMAL`、`RESET`、`ESTIMATED`、`SUSPECT`，不能把缺失补成 0 后宣称精确。

**明确不改**：不在 BFF 重新计算设备里程；不把 GPS 距离或任务路径长度混入设备里程；不改变已有接口时间参数格式。

### PROD-009：publisher 进程与媒体资源清理

**必须保证**：同一源/房间只允许一个 publisher；viewer 停止只解除自身绑定；最后 viewer、Token 过期、MQTT 断开、进程退出和异常重启均触发清理；固定摄像头按 `sessionId` 精确停止。

**部署边界**：容器启用 init 进程；为 publisher 数量、异常退出、清理延迟和 LiveKit 房间残留配置监控；清理告警阈值不高于 60 秒。生产不得使用无法回收子进程的自定义启动脚本。

**明确不改**：不因单个 viewer 离开停止共享 publisher；不通过无限延长 Token 掩盖清理问题；不让固定摄像头 stop 影响同 Gateway 其他会话。

### PROD-010：生产节点时钟同步

**必须整改**：应用节点、Keycloak、MQTT、LiveKit 和运维取证端必须使用同一组可信内网
NTP 源或可追溯的上游时钟。禁止以 `127.127.1.1` 本地伪时钟源作为生产同步已成功证据。

**整改边界**：先由运维确定权威时钟源和所有受影响节点，采用可控的渐进校时；不在业务代码中
增加数分钟容差来掩盖时钟漂移。校时后重新验证 JWT 过期、`4001/4003` 重连、30 秒授权快照、
Gateway 心跳和 120 秒健康过期。

**本次确认结果（2026-08-24）**：`.234` 的 chrony 配置指向 `192.168.124.58`，但实际
Reference ID 为 `7F7F0101`（`127.127.1.1`）；与操作端同时采样约慢 392 秒。`.58` 当前网络
不可达，向 `.58`、`.235` 和公网 NTP 发起只读查询均未获得有效响应，因此本次不擅自修改
`chrony.conf`，也不执行会造成 Token、日志时间线和租约同时跳变的强制校时。

**已落地门禁**：在每个节点本机执行 `MAX_OFFSET_SECONDS=1 sh scripts/check-time-sync.sh`。
脚本拒绝空源、`127.127.1.1`、Stratum 16 及以上、非 `Normal` Leap 状态和绝对偏差超过 1 秒；
脚本只读，不修改系统时间。运维必须补充权威源地址、网络放通、校时窗口、回退方案和节点清单，
全部通过后本项才能关闭。

### PROD-011：OIDC 回调参数清理

**必须整改**：只有在 OIDC `code` 交换成功并恢复已保存业务路由后，才能调用
`history.replaceState` 删除 `code/state/session_state/iss` 参数；清理不得触发第二次登录或丢失 hash 路由。

**明确不改**：不降低 `state`/PKCE 校验，不把授权码改存入 localStorage/sessionStorage，不为了避免显示参数
而改用隐式流程。

**实现闭环**：`keycloak.init` 返回已认证后，前端仅在 URL 同时存在 `code` 与 `state` 时删除
`code/state/session_state/iss`。使用 `history.replaceState` 保留当前 history state、业务查询参数、
pathname 和 hash，不刷新页面；Token 交换失败或回调参数不完整时不清理，便于错误诊断。

### PROD-012：Management 任务聚合的慢请求与失效引用

**必须整改**：先区分“任务实例已删除/不可见”和“Management 超时”；404 应清理或隔离失效引用，
超时应返回明确的数据降级标记并受并发上限保护。不得把超时或 404 静默补成“任务为 0”并宣称数据完整。

**验收边界**：使用真实已删除引用、Management 404、连接超时和读超时分别演练，记录 Overview
响应时间、降级字段和 BFF 执行器队列；本项不要求改变 Management 任务本身的权限模型。

**实现闭环**：

- Management 任务专用客户端默认连接超时 1000 ms、读取超时 1500 ms，代码分别硬限制在
  100 至 5000 ms、100 至 10000 ms；单 BFF 实例最多 8 个并发任务请求，等待许可 100 ms 后
  快速降级。并发配置硬限制为 1 至 32。
- 全景异步执行器固定使用 8 至 16 线程和 128 有界队列，饱和时拒绝新任务聚合，不回退到
  HTTP 请求线程执行。
- 任务实例/流程定义详情 404 视为已删除引用：隔离该引用，保留仍可用的计划和任务，并返回
  `WORKFLOW_INSTANCE_NOT_FOUND` 或 `WORKFLOW_DEFINITION_NOT_FOUND`；最多回传 20 个引用 ID。
- `/panorama/overview`、`/panorama/tasks`、统计 Overview 均返回 `dataQuality.tasks`。超时、并发饱和、
  分页上限和无效响应分别使用稳定 reason code；401/403 原样失败，不能伪装为降级成功。
- 大屏全景和统计页面看到 `degraded=true` 时使用“--”或空态并提示“任务数据暂不完整”，不得把
  空集合、任务总数和完成率显示为真实的 0；已成功加载的任务仍可展示。

**数据质量最小结构**：`complete`、`degraded`、`reasonCodes`。全景任务额外返回
`invalidReferenceCount`、`invalidWorkflowReferences`、`executor` 和 `managementConcurrency`，
供联调与容量验收；这些容量字段不是长期监控系统的替代品。

### PROD-013：语音重采样模块导出不匹配

**整改对象**：仅限 `robot-ui/src/utils/voiceWebsocket.js` 的依赖导入和重采样调用，以及对应
浏览器侧测试。当前依赖 `wave-resampler@1.0.0` 暴露的是命名导出 `resample`，生产构建已明确
报告默认导出不存在。

**整改边界**：改为命名导入或等价的受测调用方式；覆盖无需转换、上采样、下采样、单双声道
及长时间连续音频。不得借此修改 WebSocket 消息结构、采样率协商、编码格式或服务端语音协议。

### PROD-014：云台组件与 mixin 文件名大小写冲突

**整改对象**：`robot-ui/src/views/bi/patrol/monitor/second/components/` 中的 `Yuntai.vue` 组件、
`yuntai.js` mixin 及全部直接/间接导入。

**整改边界**：将 mixin 重命名为例如 `ptz-control-mixin.js` 的不冲突名称，并一次性更新静态导入
和动态路由上下文；不得改变云台动作枚举、控制参数、权限判断或 UI 行为。必须分别在大小写不敏感
和大小写敏感文件系统完成构建与基础控制验证，不能只通过关闭 CaseSensitivePaths 检查掩盖问题。

## 4. 上线门槛

P0 项必须在生产前关闭；P1 项必须有明确的延期审批和监控措施。任何文档中出现“当前代码已支持”并不等于部署已生效，必须以目标环境的路由、ACL、日志和端到端调用证据为准。
