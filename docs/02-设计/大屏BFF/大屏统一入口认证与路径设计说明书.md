# 大屏统一入口认证与路径设计说明书

> 版本：V1.0
> 状态：生产入口已切换，主要页面操作已确认
> 核对日期：2026-10-20

## 1. 目标与边界

大屏浏览器的用户 HTTP 请求使用 IAM/Keycloak 登录令牌，经同源 `/api-gw` 进入 IAM API Gateway，再按路径送到大屏 BFF、Management 或其他公开服务。网关负责令牌和入口级调用授权；BFF 负责大屏聚合、路由及自身资源操作的授权；Management 负责其业务权限和数据范围。浏览器 WebSocket 与带短期播放签名的 HLS 请求保留各自明确的同源入口，由目标服务校验对应凭据。

本方案只处理大屏用户入口。机器人 HTTP 文件上传是设备调用链，需要单独确定设备凭据与入口，不应把用户 JWT 或浏览器菜单权限用于机器人。

## 2. 已核实的调用链

| 请求 | 当前浏览器入口 | 当前实际去向 | 身份及授权 |
| --- | --- | --- | --- |
| 管理端 HTTP | `/api-gw/api/v1/management/**`、`/api-gw/api/v1/control/**` | 管理端 Nginx → IAM API Gateway → EIOP 服务 | 网关验证用户 JWT 和 `ApiEndpoint` 调用授权；Management 再检查本地业务权限和数据范围。 |
| 大屏正式前端 HTTP（4443） | `/api-gw/api/bigscreen/**` | 大屏 Nginx → IAM API Gateway → Bigscreen BFF | 网关验证 JWT、来源和入口授权；BFF 再验证 JWT 及 `bigscreen-web`/`field-app` 客户端路由权限。BFF 调用 Management 时透传用户 JWT。 |
| 大屏测试入口 HTTP（24443） | `/api-gw/api/bigscreen/**` | 测试 Nginx → 测试 Bigscreen BFF 地址 | 目前没有独立测试 BFF 运行，该入口不作为生产切换的验收环境。 |
| 大屏历史直连 HTTP | `/api/**` | 大屏 Nginx → Bigscreen BFF | BFF 验证 JWT；不经过网关。切换前有实际请求，切换后尚未确认调用方全部迁移。 |
| 大屏 WebSocket | `/ws/bigscreen` | 大屏 Nginx → Bigscreen BFF | 握手使用用户 JWT；与管理端 `/ws/control` 直达 Control 的模式一致。 |
| HLS 播放片段 | `/api-gw/api/bigscreen/control/files/{fileId}/hls/**` | 大屏 Nginx 改写后直达 Bigscreen BFF 的 `/api/control/files/{fileId}/hls/**` | 浏览器媒体元素无法携带用户 Bearer；下游校验短期播放签名。 |

IAM API Gateway 的运行包已有 `/api/bigscreen/**` 到 BFF 的路由，并要求 `api-gateway` audience 和 `ApiEndpoint api:invoke` 授权。Management 当前代码及运行包会为受管用户同步 `* /api/bigscreen/**` 授权；运行 IAM 数据中已有活动授权。运行 Keycloak 的 `bigscreen-web` 和 `field-app` 客户端均配置了 `api-gateway` audience。上述配置说明路由和基础授权条件已经具备，但不能代替实际用户令牌的端到端验证。

2026-10-20 已用授权码加 PKCE 流程签发的 `bigscreen-web` 和 `field-app` 测试令牌验证网关到 BFF 的入口。生产大屏来源已加入网关 CORS 允许列表，带该 `Origin` 的请求可以通过网关；生产 4443 的大屏普通 REST 已经由网关转发 BFF。用户已确认 Chrome 页面的任务产物进度与录像播放正常。实际执行结果与未验收项见[预检执行记录](../../04-测试与验收/执行记录/大屏统一入口迁移预检执行记录-20261020.md)和[切换执行记录](../../04-测试与验收/执行记录/大屏统一入口切换执行记录-20261020.md)。

网关运行包中已检查的认证过滤器为下游设置 `X-Subject-*`，没有发现覆盖 `Authorization` 的代码。BFF 不以这些 `X-Subject-*` 作为身份来源，而是自行验证 JWT，并从已验证的令牌重建发往下游的用户身份头。历史 Nginx 注释所述“网关替换浏览器令牌”尚无当前运行证据支持，不能据此确定根因。

## 3. 当前需要解决的问题

1. 生产 4443 的大屏普通 REST 当前经网关转发 BFF。网关的 CORS 允许来源必须包含大屏实际访问协议、主机和端口；遗漏时，浏览器带 `Origin` 的请求会在网关入口被 HTTP 403 拒绝。24443 测试入口仍直达测试 BFF 地址，但目前没有独立测试服务；两套入口不能混作同一验收环境。
2. 大屏 Nginx 的 `/api/**` 直达 BFF 在切换前有 Dart HTTP 客户端和 `localhost:8080/bi` 开发页面调用；本仓库开发代理也确实把普通大屏请求改写到该直连路径。生产切换后至 2026-10-20 22:40 暂未观察到新直连请求，但这不能证明调用方已经迁移。本机当前可见的 `eiop-app` Flutter 源码把全景、任务、控制和统计 REST 指向 `/api/bigscreen/**` 直连入口，也实现了文件 `download-url` 调用；其部分业务仍使用 Mock，实际安装包与源码的对应关系尚未核实。直连入口清理时应把 App 当前使用范围与本地联调流量逐项列明，确认安装包已经迁移且没有其他调用方后再停用。
3. BFF 通配代理同时接收 `/api/bigscreen/**`、`/api/control/**`、`/api/media/**`、`/api/manage/**` 和 `/api/v1/management/**`；其中普通 `/api/bigscreen/**` 默认改写到 Control。公开路径未充分体现 BFF 自有资源与下游服务归属，新增路径容易误入通配代理。
4. 大屏 Nginx 的通用网关位置仍会把查询参数 `access_token` 改写成 `Authorization`，同时保留原查询参数；生产大屏普通 REST 专用位置向网关透传原始 Header。BFF 对文件正文路径仍允许查询令牌；Header 与 Query 同时提供 Bearer 的请求返回 HTTP 400。文件正文的查询令牌调用方式仍需收敛，避免身份同时出现在 Header 与 URL。
5. Gateway 的粗粒度授权、BFF 的 JWT 客户端限制、Management 的业务及数据授权是三种不同检查。`* /api/bigscreen/**` 不等于大屏菜单权限，也不替代 Control/Media 的资源操作授权。
6. 网关拒绝、BFF 拒绝和 Management 拒绝的状态码与响应体并不完全相同。大屏前端需要分别处理登录失效、入口授权失败、业务权限不足及依赖异常。
7. 当前没有独立测试环境。生产和测试 Nginx 入口共用同一个 IAM API Gateway 上游，而该网关的大屏路由指向生产 BFF，测试 BFF 预期端口没有服务监听。24443 的 `/api-gw/api/bigscreen/**` 仍靠 Nginx 特例指向测试 BFF；若删除此特例，测试请求会进入生产 BFF。后续启用测试入口前须建立独立测试路由，不能让测试入口悄然转到生产 BFF，也不能用浏览器 Header 自选后端。
8. 当前 BFF、Control、Media 和 IAM API Gateway 的宿主机端口均绑定所有网络接口。生产 Nginx 已将大屏普通 REST 指向网关，但可达这些端口的调用方仍可直连服务。BFF 和 Control 的访问网络应按真实服务调用方收敛；Media 的机器人上传入口需与用户 HTTP 入口分开治理，不能简单改成只监听本机。

## 4. 目标路径与职责

| 路径类别 | 对外入口 | 入口后去向 | 负责校验 |
| --- | --- | --- | --- |
| 大屏普通 REST，包括聚合、业务代理、控制和文件元数据操作 | `/api-gw/api/bigscreen/**` | Nginx → IAM API Gateway → Bigscreen BFF | 网关检查用户 JWT 和入口授权；BFF 检查客户端及自身资源操作；EIOP 数据操作继续由 Management 检查业务权限与数据范围。 |
| 管理端公开 REST | `/api-gw/api/v1/management/**`、`/api-gw/api/v1/control/**` | Nginx → IAM API Gateway → EIOP | 保持现有网关与 EIOP 授权边界。 |
| 大屏 WebSocket | `/ws/bigscreen` | Nginx → Bigscreen BFF | BFF 在握手时验证用户身份，并在消息处理时执行现有会话和资源校验。 |
| HLS 片段 | 现有同源签名播放路径 | Nginx → Bigscreen BFF → 文件服务 | 播放签名由文件服务验证；不得把短期播放签名当作 IAM 用户 JWT。 |
| 机器人文件上传 | 独立设备调用入口 | 由设备 HTTP 鉴权方案确定 | 设备身份与 Management 设备档案对应关系另行定义。 |

`/api-gw` 是浏览器的入口前缀，网关路由中的路径为去掉此前缀后的 `/api/...`。BFF 对外只应长期提供大屏拥有的 `/api/bigscreen/**` 契约；Management 资源路径在内部代理时继续使用其真实 `/api/v1/management/**` 路径。旧 `/api/**` 直连及 BFF 通配代理的其他别名要按实际消费者逐项收口，避免永久保留两套公开入口。

入口收敛还需要网络层配合：BFF、Control 等服务端口只允许明确的内部调用方到达；网关和 Nginx 只暴露对应用户入口。Media 的设备上传入口保留机器人可达性，待设备 HTTP 凭据与设备档案绑定方案落地后按调用方收紧；不得仅凭改动大屏 Nginx 宣称全平台 HTTP 已统一鉴权。

Nginx 切换大屏普通 REST 时，须将 `/api-gw` 前缀剥离后把完整 `/api/bigscreen/**` 路径交给网关，不能让专用 `location` 的 `proxy_pass` 再剥掉 `/api/bigscreen/`。普通请求保留浏览器原始 `Authorization`；不得在该位置把 `access_token` 查询参数同时提升为 Header 并保留在 URL。HLS 专用位置仍需优先于普通 REST 匹配。测试入口保持隔离，直连 `/api/**` 在调用方迁移完成前按清单保留。

网关部署时，`GATEWAY_CORS_ALLOWED_ORIGIN_PATTERNS` 应包含正式大屏的完整来源 `https://<bigscreen-host>:<https-port>`，并保留管理端已有来源。浏览器 POST 的 `Origin` 需要在网关入口通过来源检查；来源拒绝先于 BFF 业务授权，不能用不带 `Origin` 的接口探测代替浏览器验证。
IAM 离线安装脚本会重新生成其 `.env.runtime`，部署或重装后应执行[来源配置检查](../../../deploy/docker/README.md#51-只改-env-容器环境变量)，核对环境文件和 Gateway 容器都已加载大屏来源。

## 5. 迁移顺序

1. **锁定现网调用方。** 对 `/api/**` 直连按路径、客户端类别和部署来源做脱敏统计；逐项确认所有者。检查文件正文查询令牌、下载地址、HLS、WebSocket 的真实调用方式。不得将原始令牌、完整签名 URL 或用户凭据写入日志及文档。
2. **确定验证环境与路由边界。** 当前没有独立测试环境，不切换 24443 测试入口，也不让它复用指向生产 BFF 的网关路由。优先补齐隔离的测试 BFF 与测试网关；如本轮只切换 4443 正式入口，则先用现有生产网关完成不改变公开路由的验证，并安排可回退的受控发布。执行记录须明确生产验证不能代替独立测试环境验收。
3. **完成影子验证。** 使用大屏正式客户端签发的测试用户 JWT，以及正式页面实际登录用户的令牌，通过生产 IAM API Gateway 直达 BFF 现有 REST 接口，核对 200、401、403、超时及 Management 二次授权结果。覆盖文件下载地址、播放地址和任务产物进度等 POST 请求，验证网关未改变传给 BFF 和 Management 的用户身份；逐个核对实际用户的入口授权及拒绝原因。此阶段不切换公开路由。
4. **收敛令牌处理。** 普通 REST 统一使用 `Authorization: Bearer <用户JWT>`。对确需无 Header 的文件正文读取，明确保留受限查询令牌路径或改为短期文件地址，并保证一请求只出现一种 Bearer 来源；HLS 仍使用独立播放签名。
5. **切换正式大屏 REST 入口。** 完成第 3、4 步且具备监测和回退条件后，在受控发布窗口只将 4443 Nginx 的 `/api-gw/api/bigscreen/**` 指向生产 IAM API Gateway；浏览器 URL 保持不变。`/ws/bigscreen` 和 HLS 例外按第 4 节保留，24443 测试入口保持原路由且明确不可作为本次验收环境。部署脚本默认跳过已存在的 Nginx 配置，应备份现网已渲染配置、只替换目标位置、执行 `nginx -t` 后重载；不要通过覆盖全部工作区配置来实施这处修改。发布后逐项执行真实浏览器及下游链路验证，出现授权、路径或依赖异常时立即恢复旧配置并重载。
6. **清理旧入口。** 本地联调与 Demo App 调用改走统一入口或停止使用；核对其运行构建与源码的差异后，逐项删除没有正式消费者的 `/api/**` 直达规则和 BFF 别名。仍有活跃消费者时，记录所有者、停用条件和最终日期，不把兼容路径写成长期正式契约。
7. **同步契约。** 更新大屏登录指南、BFF 接口文档、部署说明及 EIOP 中遗漏 `/api/bigscreen/**` 授权的说明和测试断言。文档只描述生效的正式规则；实施记录单独保存验证证据。

## 6. 验收与恢复

完整验收须取得以下证据：24443 测试入口保持现有路由且不会转到生产 BFF；正式大屏客户端令牌经生产网关调用 BFF 成功；无令牌、过期令牌、缺少入口授权和缺少 EIOP 业务权限分别得到预期拒绝；Management 收到的仍是原用户身份；大屏聚合、任务、视频会话、文件上传与下载的浏览器请求可用；HLS、WebSocket 和断线重连可用；直连 `/api/**` 调用方已迁移或被明确列入有期限的兼容清单。没有独立测试环境的限制必须保留在执行记录中，真实设备、媒体播放与跨服务联调分别记录，不以接口静态检查代替。已完成和未完成项目以执行记录为准。

切换只调整入口路由，不同时更改 BFF 业务语义。若网关授权、转发或下游身份出现异常，恢复此前 Nginx 大屏 REST 路由并保留故障请求的脱敏追踪号；修复原因并重新完成上述验证后再切换。旧直连入口只在其消费者迁移验收后清理。
