# 机器人主动呼叫中心端对讲验收用例

| 文档属性 | 内容 |
| --- | --- |
| 文档状态 | 现有验收口径整理 |
| 关联设计 | `../../02-设计/语音对讲/机器人主动呼叫中心端对讲设计说明书.md` |

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| CALL-001 | 机器人呼叫，中心端接听 | 双方建立语音对讲 |
| CALL-002 | 中心端拒接或无人接听 | 机器人分别收到 `rejected` 或 `timeout` |
| CALL-003 | 已有对讲时再次呼叫 | 新呼叫收到 `busy`，原通话不中断 |
| CALL-004 | 多个前端同时收到来电，一个接听 | 接听者进入对讲，其他前端同步关闭弹窗 |
| CALL-005 | 接听时机器人离线或音频桥失败 | 前端收到明确失败状态，不遗留占用 |
| CALL-006 | 机器人取消来电 | 前端关闭对应来电提示 |
| CALL-007 | WebSocket 断开后恢复 | 未超时来电可以恢复 |
| CALL-008 | 通话中切换本地麦克风或扬声器静音 | 只影响本地采集或播放，不下发设备控制命令 |
| CALL-009 | 语音通话中开启或关闭视频 | 视频 Track 独立启停，语音不中断 |
| CALL-010 | 多机器人同时呼叫 | 来电独立管理，不覆盖当前通话 |
| CALL-011 | 同一操作员或客户端发起第二通对讲 | 服务端拒绝并提示先结束当前通话 |
| CALL-012 | 重复挂断或服务端已释放 | 按已结束处理，不暴露无意义冲突错误 |
| CALL-013 | 服务重启 | 旧来电和通话不恢复，机器人可以重新呼叫 |
