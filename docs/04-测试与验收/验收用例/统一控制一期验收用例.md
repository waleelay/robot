# 统一控制一期验收用例

| 文档属性 | 内容 |
| --- | --- |
| 文档状态 | 现有验收口径整理 |
| 关联设计 | `../../02-设计/统一控制/具身智能装备统一控制一期设计说明书.md` |
| 关联接口 | `../../03-接口与协议/统一控制/控制服务接口文档.md` |

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| CONTROL1-001 | 查询不同机器人控制画像 | 前端按 `control-profile` 动态展示对应上装控制面板 |
| CONTROL1-002 | 两个终端申请同一本体控制权 | 不能同时获得控制权 |
| CONTROL1-003 | 一个终端控制本体，另一终端申请云台 | 按配置允许设备级并行控制 |
| CONTROL1-004 | 本体或云台点触、长按 | 前端按 10Hz 发送控制帧，后端逐帧校验和组装 MQTT |
| CONTROL1-005 | 无 confirmToken 或安全条件不满足时执行高风险动作 | 服务端拒绝操作 |
| CONTROL1-006 | `导航模式`下申请手动控制 | 必须完成 takeover 并等待机器人确认`手动模式` |
| CONTROL1-007 | 请求携带旧 `observedStateSeq` | 返回 `ROBOT_STATE_CHANGED` |
| CONTROL1-008 | 机器人持续上报状态 | 服务端刷新在线、模式、任务、摄像头和设备状态 |
| CONTROL1-009 | 管理端登记多合一设备和 actions | 大屏动态展示多合一面板，不登记时不展示 |
| CONTROL1-010 | 操作音量、TTS、文件、警报、照明和俯仰 | 使用统一 action/params 并发布到 `control/multi-function/command`，下层协议不暴露给前端 |
| CONTROL1-011 | 分别启停喊话、收音和“喊话时禁用收音” | 两个音频方向独立，禁用收音不结束 `monitorActive` |
| CONTROL1-012 | 只调整照明亮度 | MQTT `params` 只包含 `brightness`，不覆盖其他灯光设置 |
| CONTROL1-013 | 多合一设备缺少播放、警报或照明状态接口 | 页面保留最近下发值但不标记为设备真实状态，客户端状态不伪造这些字段 |
| CONTROL1-014 | 工控机运行多合一只读测试 | TCP `8519` 连接成功，解析真实音量、音量上限和温度；HTTP `8222` 返回真实文件列表 |
| CONTROL1-015 | 从大屏调整音量、TTS、警报、照明和两个俯仰 | MQTT action 被客户端转为抓包确认的 TCP/HTTP 报文，真实设备产生对应动作 |
| CONTROL1-016 | 多合一设备断开并恢复网络 | `connected/onlineStatus` 变为离线，客户端有界重连后恢复真实状态上报 |
| CONTROL1-017 | 大屏实时喊话与收音 | LiveKit 会话、重采样、Opus 编解码、`[10]/[40]` 双向帧和停止释放全部闭环后方可通过 |
| CONTROL1-018 | 依次把音量设置为 20% 和 10% | 设备分别生效；客户端兼容 `[14]"14"` 与 `[14]"a"`，页面最终显示 10% |
| CONTROL1-019 | 收音 Opus 帧中包含 `0x8D` | 不误拆为灯光帧，单个坏帧不会终止后续收音 |
| CONTROL1-020 | 收音开启时开始喊话 | 自动发送 `[45]` 暂停收音但保持会话，停止喊话后发送 `[46]` 恢复 |
| CONTROL1-021 | 保持媒体客户端心跳，仅停止边缘状态 Topic | 30～31 秒内 Control 产生 `OFFLINE_SCAN`，已登录大屏无需刷新动态显示离线 |
| CONTROL1-022 | 离线后恢复第一条合法、非 retained 边缘状态 | Control 立即更新为 `online`；健康明确异常时为 `fault`，Overview 与 WebSocket 一致 |
| CONTROL1-023 | 同一秒内离线后恢复，或人为乱序转发新旧状态事件 | `statusChangedAt` 保持严格递增，前端拒绝旧状态覆盖 |
| CONTROL1-024 | 并发执行边缘状态更新、超时扫描、Overview 刷新和多标签页消费 | 单设备状态更新不出现半更新载荷或状态倒退，所有页面最终一致 |
