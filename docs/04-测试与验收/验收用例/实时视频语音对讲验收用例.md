# 实时视频语音对讲验收用例

| 文档属性 | 内容 |
| --- | --- |
| 文档状态 | 现有验收口径整理 |
| 关联设计 | `../../02-设计/语音对讲/实时视频语音对讲设计说明书.md` |

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| INTERCOM-001 | 未观看视频直接点击通话 | 创建或复用视频 Room，仅激活音频 Track，通话成功 |
| INTERCOM-002 | 通话中打开绑定摄像头视频 | 原通话不中断，新增视频 Track 并播放 |
| INTERCOM-003 | 通话中关闭视频画面 | 停止当前视频观看，音频连接和麦克风发布保持 |
| INTERCOM-004 | 无观看者但通话持续 30 分钟以上 | Room 不被视频空闲策略释放 |
| INTERCOM-005 | 通话中打开其他摄像头 | 新视频正常观看，原 Room 语音不中断 |
| INTERCOM-006 | 挂断后无人观看 | 会话按延迟释放策略关闭 |
| INTERCOM-007 | 两个用户同时请求讲话 | 仅一个用户获得发布权限，另一方收到占用提示 |
| INTERCOM-008 | 机器人离线或网络中断 | 前端收到异常事件，对讲结束或明确要求重新发起 |
| INTERCOM-009 | 接听等待中退出页面，随后收到迟到的连接成功 | 页面不重新打开麦克风，迟到 Room 被再次断开 |
| INTERCOM-010 | 用户拒接或接听超时后，乱序收到同一 callId 的 accepted | 不激活通话，立即向服务端发送挂断 |
| INTERCOM-011 | LiveKit disconnect Promise 永久不返回 | 麦克风立即停止，本地状态和通话租约最迟 3 秒完成释放 |
| INTERCOM-012 | 正在观看视频时结束对讲 | 麦克风关闭，视频 Room 和画面保持 |
| INTERCOM-013 | 普通对讲与现场视频呼叫同时发起 | 只有一个入口取得浏览器麦克风租约，另一入口提示占用 |
| INTERCOM-014 | 边缘端不带更新时间，连续上报相同 volume/muted | 每次上报均可撤销命令乐观值，最终显示与设备状态一致 |
| INTERCOM-015 | 新版本发布时旧页面再进入懒加载路由 | 旧哈希 JS/CSS 在宽限期内仍可加载，页面布局完整；刷新后入口加载新版本 |
| INTERCOM-016 | 多合一控制与普通扬声器音量、普通对讲并存 | 多合一仍使用原独立设备和控制流程，不被普通扬声器映射或通话租约改写 |
