## 1. 主流程

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| VIDEO-001 | 客户端在线，RTSP 可访问 | 前端选择摄像头并创建观看会话 | 创建 Room，签发 publisher/viewer Token，MQTT 下发 start |
| VIDEO-002 | 已下发 start | 观察客户端和服务端状态 | 客户端依次上报 publishing、streaming，服务端进入 `STREAMING` |
| VIDEO-003 | 会话为 `STREAMING` | 前端连接 LiveKit | 订阅目标视频 Track 并显示画面 |
| VIDEO-004 | 正在观看 | 停止最后一个 viewer | 会话进入 `IDLE_WAIT`，到期下发 stop，客户端停止推流并关闭会话 |

## 2. 多路与多人观看

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| VIDEO-010 | 至少两路摄像头可用 | 同时打开两路视频，再停止其中一路 | 只停止目标 `sessionId`，另一路继续播放 |
| VIDEO-011 | 浏览器 A 正在观看一路视频 | 浏览器 B 观看同一路视频 | `viewerCount=2`，不重复启动机器人推流 |
| VIDEO-012 | A、B 正在观看同一路 | B 停止观看 | `viewerCount=1`，A 不断流、不重连 |
| VIDEO-013 | 视频墙环境准备完成 | 打开多路视频墙 | 活跃列表不超过 16 路，默认使用 `sub` |

## 3. 通道与清晰度

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| VIDEO-020 | 双光摄像头配置完整 | 分别观看 `visible.sub`、`visible.main`、`thermal.sub`、`thermal.main` | 每个组合均订阅正确 Track |
| VIDEO-021 | 正在观看一路视频 | 切换通道或清晰度 | 重新下发 publisher Token，前端重新订阅目标 Track |

## 4. 抓拍与录像

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| VIDEO-030 | 未观看视频 | 检查抓拍入口 | 抓拍按钮不可用 |
| VIDEO-031 | 正在观看 | 执行即时抓拍 | 前端截取 JPEG，按通用文件接口上传 `IMAGE`，最终文件状态为 `READY` |
| VIDEO-032 | 抓拍完成 | 打开图片预览 | 返回 `image/jpeg`，对象存储中存在正式图片 |
| VIDEO-033 | 限制上传大小或关闭 MinIO | 执行抓拍上传 | HTTP 返回明确文件错误，不生成 `snapshot.*` 任务事件 |
| VIDEO-034 | 正在观看且录像能力可用 | 开始并停止录像 | 录像文件进入统一文件处理流程，最终可查询和播放 |

## 5. WebSocket 与异常恢复

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| VIDEO-040 | 服务已启动 | 分别直连 Media `/ws/media`、Control `/ws/control`、BFF `/ws/media` | 直连 Media 收媒体 `video.*`/TTS；Control/BFF 路径收 Control 事件，不把 BFF `/ws/media` 当作 Media 直连 |
| VIDEO-041 | 已直连 Media WebSocket | 创建、切换、停止视频 | 收到对应 `video.*` 状态；抓拍成功以文件 HTTP 响应为准 |
| VIDEO-042 | 正在观看 | 直接关闭浏览器 | viewer heartbeat 超时后自动清理，人数下降 |
| VIDEO-043 | 正在观看 | 断开机器人网络后恢复 | 机器人先变为离线；重新上线后有观看者的会话自动恢复 |
| VIDEO-044 | WebSocket 短暂中断 | 恢复连接 | 前端重新取得会话状态，不重复创建推流 |

## 7. 固定摄像头

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| VIDEO-060 | Management 已启用摄像头，Gateway 在线 | 启动单路固定摄像头 | `sourceType=FIXED_CAMERA`，Room 名包含 `media.fixed`，Gateway 发布 Track |
| VIDEO-061 | 仅配置主码流 | 请求 `quality=sub` | Control 回退到 `main`，响应和 Track 清晰度一致 |
| VIDEO-062 | 两路有效、一路无码流 | 调用批量启动 | `sessions` 保留成功项，`failures` 标明失败 cameraId 和原因 |
| VIDEO-063 | 固定摄像头正在推流 | 停止最后 viewer 并等待空闲释放 | Gateway 只停止目标 session，Room 关闭，其他画面不受影响 |
| VIDEO-064 | BFF 返回固定摄像头 | 检查展示字段 | 不返回 RTSP URL；分别返回配置、Gateway 和流健康；只有三者满足时 `status=online` |
| VIDEO-065 | `enabled=true`，Gateway 未启动或 Control 刚重启 | 查询 Overview 和统计 | 固定摄像头为 `unknown/offline`，不得计入 `online` |
| VIDEO-066 | Gateway 连续心跳后停止进程 | 等待 30 秒并查询 | Gateway 不超过 30 秒转 `OFFLINE`，页面阻止播放；恢复心跳后恢复 `ONLINE` |
| VIDEO-067 | Gateway 在线，RTSP 地址不可达 | 等待一次探测或发起播放 | `streamHealth=UNAVAILABLE`、通用状态为 `offline`，会话返回 `RTSP_PROBE_FAILED` |
| VIDEO-068 | 最近 RTSP 状态超过 120 秒未更新 | 查询健康和 Overview | `streamHealth=UNKNOWN` 且不沿用旧 `online` |
| VIDEO-069 | 构造 Topic 与 payload ID 不一致或乱序消息 | 发布 MQTT 状态 | Control 拒绝消息，现有新状态不被覆盖 |
| VIDEO-070 | 同一用户只授权部分固定摄像头 | 查询健康并接收变化事件 | 健康接口只返回授权摄像头；事件仅触发当前用户重拉，不泄露其他摄像头 ID |
| VIDEO-071 | 健康扫描耗时超过扫描周期且摄像头超过一页 | 观察 Gateway | 扫描完整翻页；重叠轮次跳过；实际探测并发不超过配置值 |
