## 实现与审查

1. 注册表显式列出 `robot.state.data` 输出字段，移除重复设备列表、内部客户端标识、重复时间和原始诊断。
   保留首屏兜底名称/类型、摄像头路由、本体状态、位置、状态来源、健康值和版本信息。
2. Control 统一投影 `deviceRuntime.devices[].status`，嵌套对象同样限制字段。
   普通音量与警示灯输入别名仅在规范键缺省时归一；null、false、0 不被别名覆盖。
   HTTP `deviceRuntime`、已有 HTTP 合并 `devices` 的状态、媒体与边缘触发的推送共用投影。
   投影不读取 Management 类型、当前请求身份或缓存；同一版本不能因画像命中情况变化而改变。
3. 原始客户端状态仍供服务内部驱动音频关联与命令校验使用。
   本次没有删减发射器安全检查、控制租约、MQTT 发布或里程采集逻辑。
4. robot-ui 移除从旧 `devices` 构造运行态和定义的回退，只按平台 ID 合并静态定义与版本快照。
   旧事件字段不再扩散到页面；普通音量与警示灯只读规范字段。
   控制命令响应中的 `controlModeName` 仍有消费者，保留。
5. BFF 原始事件转发、权限和状态来源过滤保留；派生状态事件同步移除冗余字段。
   故障判定、定位事件、统计失效、本体运行态及在线版本仍保留。
6. 多合一组件温度、音量上限、文件列表、传输、媒体会话和播放字段均保留。
   缺少查询反馈时既有操作条件保持不变；不把命令发布当成设备反馈。

权威字段集合与升级边界见[客户端事件协议](../../03-接口与协议/客户端事件/客户端事件与载荷协议文档.md#42-robotstate)，
HTTP 定义见[控制服务接口](../../03-接口与协议/统一控制/控制服务接口文档.md)。
