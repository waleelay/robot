## 在线模拟与页面观察

测试进程使用 Control 容器现有 MQTT 连接配置，向 `m20s-zh002` 的边缘状态和媒体客户端状态 Topic 每 5 秒发送一次非 retained、QoS 1 消息；单轮持续 120 秒，结束时发送 `status=offline`、`devices=[]`。模拟载荷的设备身份为 `base/WHEELED_BASE` 与 `ptz_main/PTZ`，云台 `autoRotateEnabled` 在前后半段分别为 `true` 与 `false`。未模拟摄像头、音视频流或可执行命令的实体客户端。

| 核对点 | 实际观察 |
| --- | --- |
| 在线刷新 | 实时监控在线装备数由 0 变为 1，`m20s-zh002` 进入在线列表；控制中心状态从“离线”变为“空闲中” |
| 原始推送 | Control 注册表中该设备为 `status=online`，设备列表仍为 `base/WHEELED_BASE`、`ptz_main/PTZ`；后半段 `autoRotateEnabled=false` |
| 控制画像隔离 | Chrome 控制中心显示机器狗图标和一套机器狗本体控制，含“左平移/右平移/站立/趴下”；没有同时渲染轮式车本体组件。图标和组件布局与原始 `WHEELED_BASE` 推送没有交叉覆盖 |
| 云台展示 | 右侧显示“双光云台”及方向、变焦和自转控件；自转图标在 `true` 阶段高亮，后半段随 `false` 推送取消高亮 |
| 其他上装 | 扬声器、捕网器、发射器仍按测试设备已有画像显示，右侧布局未见原问题中的挤压错位 |

`m20s-zh002` 是管理端已有设备，未新增管理端设备或修改设备档案。直接在新浏览器标签页打开控制画像 API 得到 401；该直访与应用内请求的认证上下文不同，故本轮控制画像验证以已登录页面和控制中心显示为准，未把该直访当作接口失败。
