# 统一媒体 Gateway 目录与协议分层收敛执行记录

本批将固定摄像头和无人机视频的 Go 工程统一为 `media-gateway`，完成目录、依赖和部署配置收敛。
RTSP 是当前唯一生产输入协议；多协议接入和无人机平台观看接口仍未完成。媒体链路相关本地回归通过，
独立 BFF 检查的既有失败见第 6 节；本地验证不代表已部署或已完成真实视频验收。

| 日期 | 2026-10-10 |
| 环境 | 本地 macOS，仓库 Go、Java 与 Docker Compose CLI |
| 范围 | Go 模块、输入协议分层、发布接口、Compose、离线打包与配置引用 |
| 对外契约 | 保持上一批 `gateway/media/**`、源身份、目录字段和 `EDGE_MEDIA_GATEWAY` 发布模式 |
| 状态 | 收敛与审查修复完成；未执行数据库迁移、镜像构建或生产部署 |

## 1 目录与依赖

- 根目录、Go module/import、唯一命令入口统一为 `media-gateway`；原目录已迁移，残留空目录已移除。
- `internal/media` 定义通用 `Input`、`StreamInfo`、`Adapter` 和安全错误契约，不依赖 MQTT、业务源或具体协议。
- `internal/source` 管理业务源、协议注册与授权租约；输入使用 `Address`，不再使用 RTSP 专属输入类型。
- RTSP 地址校验、ffprobe 探测、编码识别与对应测试放入 `internal/protocol/rtsp`，由 `internal/app` 注册。
- `internal/gateway` 与 `internal/publisher` 使用通用输入；实际探测编码不再附加到业务启动命令。
- 租约检查通过当前源配置查询，不再以写死的 RTSP 和 main 码流判断源是否仍被授权。
- 去掉源注册表可选时的旧运行分支；统一入口始终需要受控源注册表。

通过 `go list` 检查生产导入，`media/source/gateway/publisher` 均未导入具体协议包；
`app` 导入 `protocol/rtsp` 完成组装。测试中的具体协议引用仅用于构建测试输入。

## 2 发布与升级边界

当前 Publisher 仍只支持 RTSP。新增协议必须同时实现输入适配、监听或会话协商、发布后端和资源释放，
不能通过增加枚举或测试适配器宣称已支持。未实现的发布协议与命令协议不匹配会在解绑、停止或重启现有进程前被拒绝。

Compose service/profile/container、镜像和离线包名称统一为 `media-gateway`，打包与加载脚本同步调整。
旧离线 Gateway 包不被复用或附带，新包仍检查 `edge-media-v1` 协议标签。旧运行实例不会由服务键更名自动停止，
上线前必须确认并停止旧实例，避免重复 MQTT 身份或重复推流。

发布模板的地址占位符由 `{rtsp}` 改为 `{input}`。默认配置和两套 Compose 已同步，含旧占位符的
自定义模板会在启动前明确报错。MQTT 目录仍使用 `mainStreamUrl/subStreamUrl`；命令 `rtspUrl` 仅用于
检测并拒绝未授权地址覆盖，不参与输入或发布。

BFF 固定摄像头响应中的既有 `clientId` 展示标识和前端状态 key 保持兼容；其中旧名称不是 Go 模块、
部署服务或第二套运行入口。历史验收记录与旧镜像排除规则同样保留必要的旧名称。

收尾检查修复两处环境变量错配：Control 的 Gateway ID 改为读取与 Compose/Gateway 一致的
`MEDIA_GATEWAY_ID`；固定摄像头健康超时和发布模式切换参数继续使用 Control 实际读取的
`FIXED_CAMERA_*` 名称。新增配置回归脚本用非默认实例 ID 和超时验证两套 Compose，避免 default 值掩盖错配。

## 3 实际验证

以下命令在本批执行并通过：

```bash
(cd media-gateway && go test -race -count=1 ./...)
(cd media-gateway && go vet ./...)
(cd media-gateway && go build -o /tmp/robot-media-gateway-converged ./cmd/media-gateway)
sh scripts/test-media-gateway-contract.sh
sh scripts/test-media-gateway-config.sh
docker compose -f deploy/docker/docker-compose.yml config --quiet
docker compose -f deploy/docker/docker-compose.host.yml config --quiet
sh -n scripts/dev-check.sh scripts/test-media-gateway-contract.sh scripts/test-media-gateway-config.sh \
  deploy/docker/package.sh deploy/docker/update-services.sh deploy/docker/scripts/internal/load-images.sh \
  media-gateway/scripts/ffmpeg-livekit-publisher.sh media-gateway/scripts/install-gstreamer-publisher.sh
git diff --check -- . ':!deploy/docker/config/nginx/html/tdt.tar.gz'
```

- 无缓存竞争检测覆盖正常启停、重启、异常进程退出、会话共享、租约撤销和终止水位。
- 新增测试覆盖非 RTSP 测试源的目录查询、探测和精确撤权，以及未实现发布协议不扰动已有进程。
- RTSP 测试覆盖 H.264/H.265 编码识别、空视频、未知编码、地址校验与敏感异常脱敏；H.265 发布仍直接选择转码后端。
- 跨语言脚本由真实 Java 发布器生成新 MQTT 目录和启停样例，再由 Go 消费；不使用过期租约样例，也不以跳过的测试代替验证。
- 配置脚本校验服务、profile、镜像、容器、入口和默认模板，并验证非默认 `MEDIA_GATEWAY_ID` 与健康超时在两端一致。
- 新 Go 模块及新增脚本、执行记录另做未跟踪文件空白检查，避免普通 `git diff` 漏掉新文件。

首次 `go vet` 指出通用错误结构跨包迁移后仍使用无字段名的字面量，修正后重新运行并通过。
目录收敛阶段的 Java 变更仅为环境变量占位符与注释，当时重跑了 MQTT 契约测试；后续审查验证见第 6 节。
上一批完整迁移的验证结果保留在原迁移记录，不把不同阶段的检查混写为同一结果。

## 6 审查修复与提交验证

提交审查以 `047e3f93520b6d543f99b1b03963e6c617943ae0` 为明确基线。目录收敛依赖此前未提交的
统一 MQTT、授权目录和共享发布枚举迁移，按同一 Gateway 功能闭环纳入；地图资源包与无关 BFF 测试修正排除。
文档随相关代码提交，提交编号以 Git 记录为准。

审查补充时序测试最初复现两个问题：租约在探测期间过期仍调用发布器；断网期间租约过期后终止原因
发送失败，重连只补报普通中断。这两个问题现已修复：

- 探测后和实际 Start/Restart 前再次校验租约、会话终止水位与选流；`publishing` 的 MQTT 确认等待不能绕过第二次检查。
- 租约撤权原子保存终止水位与待补报状态，再取消启动和释放绑定；成功确认前保留终止原因。
- 普通断线事件不覆盖已有终止状态；补报串行执行，发送前读取最新事实，MQTT 等待不持有状态互斥锁。
- 输入地址在探测后变化时返回 `SOURCE_INPUT_CHANGED`，前端提供安全中文提示，不把地址或凭据返回浏览器。

审查阶段重新执行 Media 220 项、Control 207 项测试，均为零失败、零错误、零跳过。
