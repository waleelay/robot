# Control 8082 访问边界整改执行记录（2026-10-21）

## 范围与原因

`CTL_SEC_006` 在现网失败：Control 信任受控上游传入的 `X-User-Id` 和 `X-Roles`，但宿主机 `8082` 曾监听所有网络接口。局域网调用方可以绕过 BFF，自行填写身份头访问 Control。整改对象是 Control 的网络入口，不改变业务接口和身份头协议。

## 调用方与发布方式

- 大屏 BFF 经 `robot-mediaserver` Docker 网络访问 `control-service:8082`；BFF 验证用户 JWT 后生成下游身份头。
- EIOP Management 的固定摄像头发布编排通过 `host.docker.internal:8082` 调用 Control。现网该名称在 Management 容器内解析为宿主机网关 `172.17.0.1`。
- 机器人状态与命令使用 MQTT，不需要从局域网直连 Control 的 HTTP 端口。

Bridge Compose 的 Control 端口增加 `CONTROL_SERVICE_BIND_ADDRESS`，默认 `127.0.0.1`。现网 `.env` 显式配置为 `172.17.0.1`，因此 Management 仍可调用，BFF 继续使用内部 Docker 网络。该地址是本次服务器的网关事实，不作为其他环境默认值。Control JAR、Management 配置、Nginx 和媒体服务未改动。

## 实施与验证

实施前，工作站请求 `192.168.124.23:8082/api/control/video-sessions` 返回 HTTP 400，Management 容器经宿主机网关请求同一路径也返回 HTTP 400，证明两处 TCP 均可达。现网 Compose 与 `.env` 分别备份为 `/home/robot-mediaserver-installer/docker-compose.yml.pre-control-port-20261021` 和 `.env.pre-control-port-20261021`；修改后执行 `docker compose config --quiet`，再仅重建 `control-service`。

实施后，容器处于 `running`、重启次数为 0；宿主机 `ss` 显示 `172.17.0.1:8082`，不再有 `0.0.0.0:8082` 或 IPv6 全接口监听。工作站携带自填身份头请求 `192.168.124.23:8082/api/control/video-sessions` 时连接失败；Management 容器经 `172.17.0.1:8082` 请求返回 HTTP 400；BFF 容器网络经 Control 容器地址请求返回 HTTP 400。两个 400 是缺少业务身份头后的应用响应，仅用于证明服务可达，不代表已验证固定摄像头发布动作。Control 启动日志显示 8082 正常启动，近五分钟未见 Control 或 BFF 新增 ERROR；正式大屏入口 `/bi/index` 返回 HTTP 200。上述结果关闭 `CTL_SEC_006` 的局域网直连分支。

## 恢复与剩余验证

如需恢复原端口发布方式，在 `/home/robot-mediaserver-installer` 用备份 Compose 和 `.env` 覆盖对应文件，先执行 `docker compose config --quiet`，再执行 `docker compose up -d --force-recreate --no-deps control-service`；恢复后须检查 Management 与 BFF 调用，并重新评估局域网直连风险。

本次未进行真实固定摄像头发布模式切换，也未使用已登录浏览器验证全景、任务列表和录像播放。容器内的其他进程仍可到达受控地址；`X-Internal-Caller` 和用户身份头不是独立的服务身份凭证。多主机部署与 `docker-compose.host.yml` 需分别配置访问边界，不能直接套用本次网关地址。
