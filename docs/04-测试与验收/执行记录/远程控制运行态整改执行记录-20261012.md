### 阻断项一：HTTP 与推送的设备身份不同

轮式设备实际采样：

| 画像 ID / HTTP 运行态 ID | WebSocket 运行态 ID | 推送中的 `status.driverDeviceId` | 当前 Vuex 后续合并 |
| --- | --- | --- | --- |
| `ptz_main` | `ptz-dual-001` | `ptz_main` | 丢失云台状态 |
| `launcher_38mm` | `launcher-001` | `launcher_38mm` | 丢失发射器状态 |
| `catcher_net` | `net-gun-001` | `catcher_net` | 丢失捕网器状态 |
| `microphone_main` | `intercom-001` | `microphone_main` | 丢失对讲设备状态 |
| `speaker_main` | `audio-control-001` | `speaker_main` | 普通扬声器别名分支能匹配，保留音量 60% |

`EquipmentControlService.deviceRuntimePayload` 有管理端档案时做 ID 投影，无档案时直接返回原始快照；`ControlManagementClient.cachedDeviceBySerialNumber` 又依赖当前 HTTP 身份，MQTT 回调没有该身份。于是 HTTP 使用画像 ID，推送使用客户端 ID，且推送仍含客户端 `deviceType`。前端只为普通扬声器做别名匹配，其他设备状态随新版推送消失。本次采样的 HTTP 与 WebSocket 版本不同；相同版本也可能生成不同投影的判断来自上述代码路径，不把采样写成同版本实测。

修正要求：同一运行态快照在 HTTP 与推送中必须保持一致，不能由请求身份决定其设备身份。正式客户端以控制画像设备 ID 上报；确需保留的别名迁移应由单一明确规则处理，冲突或无法关联时暴露诊断，不在前后端分别猜测类型或 ID。

另有数据配置不一致：轮式画像只有 `warning_light`，模拟上报为 `warning-light-left`、`warning-light-right`，其物理 ID 分别为 `light-001`、`light-002`，均不能唯一对应画像。应按实际硬件在 Management 注册两个组件并对齐平台 ID，或由客户端按一个明确的聚合组件上报；不能把两个独立状态任意合并到一个开关。

### 阻断项二：多合一控件仍把未知状态当成在线

`MultiInOne.vue.connected` 使用 `status.connected !== false`、`onlineStatus !== 'offline'`。`study` 画像包含 `broadcaster-001`，但 HTTP 和推送都没有该设备状态，空对象仍判定连接成功，在线页面已复现。该组件还保留局部音量、播放等状态，缺失字段不会统一清空；本轮分离运行态后仍未覆盖这个消费者。

修正要求：客户端在线、设备存在且明确连接成功才能放行；未知状态显示未同步或不可用。快照缺失、客户端离线、设备切换和推送失联时应清理局部设备状态与关联音频会话。静态能力可保留用于展示，不得作为在线事实。

### 阻断项三：捕网器局部断线后保留旧确认

当前 watcher 仅在 `clientOnline=false` 或机器人切换时清空 `netGunSafety`。直接调用源码 watcher 已复现：媒体客户端仍在线，单个捕网器 `connected=false` 或 `devices=[]` 时，本地安全开关记录仍为 `true`；同 ID 设备重连后旧确认再次生效。WebSocket 断开分支也未清除此记录。

修正要求：单个设备断开、设备从完整快照消失、WebSocket 断开以及退出控制页时撤销本地确认，并关闭未完成的发射确认框；恢复连接后重新确认。此项仅做本地状态验证，未在服务器或真实设备上尝试发射。

### 其他代码边界

- `expireStaleMediaClients` 在 Equipment 锁外更新 `mediaClientOnlineByRobot`；心跳可插入“超时快照生成”和“记录 false”之间。Registry 的旧版本保护能挡住设备快照回退，却不能保护独立在线转换表，后续心跳可能再次触发 `onlineRestartCommands`。这是代码时序风险，本次未在线制造并发复现，应在整改时统一状态转换的版本或串行边界。
- 旧混合 `devices[]` 的按类型兜底只检查上报源类型唯一，没有检查管理端目标类型唯一。一个旧 ID 的云台状态可能映射给两个同类型管理端组件；新运行态身份方案应一并限定兼容边界。
