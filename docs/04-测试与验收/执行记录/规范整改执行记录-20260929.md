### 3. 契约与兼容性

版本化产物：[Media 文件](../../../quality/openapi/media-files.json)、[Control 文件](../../../quality/openapi/control-files.json)、[HTTP 响应样例目录](../../../quality/openapi/fixtures)。字段、类型、null、时间、二进制和错误变体由生成契约描述；流程文档见[通用文件服务接口](../../03-接口与协议/文件服务/通用文件服务接口文档.md)。

1. Media 增加与 Control 相同的 springdoc 2.8.17；`media-common` 只依赖 Swagger 2.2.47 注解元数据，不引入 Spring 或复制业务。networknt 1.5.6 只用于测试。
2. Media 文档默认 `MEDIA_OPENAPI_ENABLED=false`；Control 保持 `CONTROL_OPENAPI_ENABLED=false`。显式开启时 Media `/v3/api-docs` 生成文件契约，Control `/v3/api-docs` 保留里程路径，文件使用 `/v3/api-docs/files` 分组。没有引入 Swagger UI。
3. 为双前缀生成稳定且不同的 operationId；Control 分组限定具体 Controller，防止混入其他路由或通配代理。原业务映射数量及签名保持不变。
4. 上传字段描述为 multipart 表单，修正生成器将表单字段重复列成必填 query 参数的问题，并添加回归断言；运行时绑定保持原样。JSON 成功响应、204 空正文、下载二进制和 HLS 媒体类型分别描述。
5. 共享响应保留实际 JSON 字段和 null；时间按现有 `Asia/Shanghai` 的 `yyyy-MM-dd HH:mm:ss` 输出，不错误声明为 RFC 3339。同步删除简单上传示例中不存在的 `uploadMode`，修正 multipart `metadata` 为 JSON 字符串，并补机器人头要求。
6. 按实际入口区分可信用户 Header、机器人标识及来源网络、HLS 播放 token、MinIO 内部 Bearer 凭证。Media 默认用户回退、Control 默认身份必填及 BFF 原有 JWT 规则没有改变。
7. 如实保留不同错误结构：Media 业务异常、框架错误、来源网络拒绝、Control 本地请求错误及上游透传。Media 当前非法数字分页参数返回 `404 NOT_FOUND`，并发合并返回 `409 UPLOAD_COMPLETION_IN_PROGRESS`；本次没有借规范整改重写错误映射。Control 透传错误状态和正文，错误响应头并不保证透传。
8. 文档补充类只服务于 Schema：动态扩展绑定仍由原 Map 处理，MinIO 回调仍使用 JsonNode；未用新的 DTO 收紧原运行时解析。

上传流关闭是本次明确的资源修复；其余生产源码修改为注释、契约元数据、无用代码清理和泛型/序列化声明。未迁移数据库、修改接口字段、收紧权限或新增第二套业务协议。
