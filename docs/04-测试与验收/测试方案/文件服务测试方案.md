## 1. 测试范围

- 小文件直接上传。
- 大文件 multipart 初始化、分片 URL、完成和取消。
- `sourceFileId` 幂等恢复和重复请求。
- 上传中断、缺失分片、文件变化、大小不一致和过期。
- 视频 HLS 后处理、状态查询、播放和下载。
- 文件查询、授权、删除和保留期清理。
- 多机器人上传会话容量和单文件分片并发控制。

## 2. 测试策略

1. 使用不同大小和类型的文件覆盖直接上传与 multipart。
2. 在分片上传中途停止客户端，再使用相同 `sourceFileId` 恢复。
3. 注入缺失分片、错误 ETag、源文件变化和重复 complete。
4. 分别验证原文件、HLS playlist、init segment 和媒体分片。
5. 验证数据库、对象存储和客户端 manifest 的状态一致。
6. 验证过期上传及删除操作正确释放对象存储资源。
7. 验证已过期 `ACTIVE` 会话不占用容量，单条清理失败不阻塞同批其他会话。
8. 验证容量达到上限返回 `429 UPLOAD_SESSION_LIMIT` 及计数详情，对象存储故障返回可重试的 `503 STORAGE_UNAVAILABLE`。

## 3. 构建与自动化测试

```bash
(cd backend && mvn test)
(cd client && go test -tags nolibopusfile ./...)
(cd python-client && python -m unittest discover -s tests)
```

## 4. 退出条件

- 正常上传、断点恢复、播放和删除链路通过。
- 幂等、并发限制和关键失败路径有执行结论。
- 数据库与对象存储不存在无法解释的残留资源。
- 未执行的容量或压测项目已记录原因和补测条件。

验收步骤见[文件服务验收用例](../验收用例/文件服务验收用例.md)。
