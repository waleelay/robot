## 1. 测试范围

- 控制画像、设备能力和真实状态聚合。
- 控制权申请、冲突、接管、释放和超时。
- `MANUAL`、`NAVIGATION` 等模式切换。
- 本体、云台和上装设备命令。
- 高风险动作确认、急停和安全限制。
- MQTT 指令、统一 `media/client/status` 状态上报、重复消息和幂等。
- WebSocket 状态同步和多终端协同。
- 二期 Action Schema、Driver、审计与回放能力。

## 2. 测试环境

至少准备 Control Service、管理服务、EMQX、一个机器人客户端和两个独立的前端客户端。高风险动作应优先使用模拟设备或明确隔离的测试设备。

## 3. 测试策略

1. 使用单元测试覆盖参数校验、限幅、权限和状态机。
2. 使用接口测试验证控制会话和错误码。
3. 订阅 MQTT Topic 核对最终下发的 `action/params`。
4. 使用两个终端验证控制权冲突和设备级并行控制。
5. 注入离线、旧 `stateSeq`、重复命令、超时和状态迟到场景。
6. 使用真实状态上报验证页面不展示伪造设备状态。
7. 对多合一设备逐项核对 action、局部灯光参数、文件名校验和独立 `multi-function` topic。
8. 验证客户端没有设备查询依据时，不把照明、警报和文件播放的最近命令参数上报为真实状态。

### 4.1 多合一设备现场测试

测试程序必须运行在能访问 `192.168.1.27` 的机器人工控机。先执行只读测试：

```bash
cd client
go build -o multi-function-test ./cmd/multi-function-test
./multi-function-test -host 192.168.1.27 -action status
./multi-function-test -host 192.168.1.27 -action list_audio_files
```

确认现场人员、设备和灯光方向安全后，再执行改变设备状态的动作：

```bash
./multi-function-test -host 192.168.1.27 -action set_volume \
  -params '{"volumePercent":30}' -execute
./multi-function-test -host 192.168.1.27 -action play_tts \
  -params '{"text":"多合一设备联调","voice":"MALE","loop":false}' -execute
./multi-function-test -host 192.168.1.27 -action light.set \
  -params '{"enabled":true,"brightness":20}' -execute
./multi-function-test -host 192.168.1.27 -action light.set \
  -params '{"enabled":false,"redBlueMode":0}' -execute
```

现场记录至少包含：执行时间、工控机 IP、设备 IP、action/params、程序输出、设备实际响应和恢复结果。当前实时喊话/收音 LiveKit 桥尚未闭环，不列入已通过项。

## 5. 退出条件

- 本次范围内验收用例全部有执行结论。
- P0/P1 缺陷关闭或完成风险接受。
- 控制权、模式和高风险动作不存在绕过路径。
- MQTT 与 WebSocket 的最终状态能够闭环。

验收步骤见[统一控制一期验收用例](../验收用例/统一控制一期验收用例.md)和[统一控制二期验收用例](../验收用例/统一控制二期验收用例.md)。
