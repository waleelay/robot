## 1. 测试范围

- 控制画像、设备能力和真实状态聚合。
- 控制权申请、冲突、接管、释放和超时。
- `MANUAL`、`NAVIGATION` 等模式切换。
- 本体、云台和上装设备命令。
- 高风险动作确认、急停和安全限制。
- MQTT 指令、ACK/status、重复消息和幂等。
- WebSocket 状态同步和多终端协同。
- 二期 Action Schema、Driver、审计与回放能力。

## 2. 测试环境

至少准备 Control Service、管理服务、EMQX、一个机器人客户端和两个独立的前端客户端。高风险动作应优先使用模拟设备或明确隔离的测试设备。

## 3. 测试策略

1. 使用单元测试覆盖参数校验、限幅、权限和状态机。
2. 使用接口测试验证控制会话和错误码。
3. 订阅 MQTT Topic 核对最终下发的 `action/params`。
4. 使用两个终端验证控制权冲突和设备级并行控制。
5. 注入离线、旧 `stateSeq`、重复命令、超时和状态迟到场景。
6. 使用真实状态上报验证页面不展示伪造设备状态。

## 4. 构建与自动化测试

```bash
(cd control-service && mvn test)
(cd client && go test -tags nolibopusfile ./...)
(cd python-client && python -m unittest discover -s tests)
(cd robot-ui && npm run lint)
(cd robot-ui && npm run build:prod)
```

## 5. 退出条件

- 本次范围内验收用例全部有执行结论。
- P0/P1 缺陷关闭或完成风险接受。
- 控制权、模式和高风险动作不存在绕过路径。
- MQTT 与 WebSocket 的最终状态能够闭环。

验收步骤见[统一控制一期验收用例](../验收用例/统一控制一期验收用例.md)和[统一控制二期验收用例](../验收用例/统一控制二期验收用例.md)。
