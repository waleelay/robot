# 项目文档索引

本目录只维护四类正式文档：需求、设计、接口与协议、测试与验收。代码结构、配置、启动、构建和模块开发说明统一放在各模块的 `README.md` 中。

## 1. 文档分类

| 目录 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| `01-需求/` | 做什么、为什么做 | 目标、范围、业务规则、功能需求、优先级、验收标准 |
| `02-设计/` | 准备怎么实现 | 架构、模块职责、数据模型、状态机、时序、异常和技术取舍 |
| `03-接口与协议/` | 系统之间如何交互 | REST、WebSocket、MQTT、事件载荷、字段映射和对接示例 |
| `04-测试与验收/` | 如何证明满足要求 | 测试范围、环境、策略、验收步骤和预期结果 |
| `归档/` | 哪些内容不再生效 | 已废止方案和历史资料，不作为当前实现依据 |

## 2. 文档命名规范

文件名使用明确的业务对象和文档类型，不使用“新版”“最终版”“确认版”等无法长期维护的后缀：

```text
<业务对象>需求说明书.md
<业务对象>设计说明书.md
<业务对象>接口文档.md
<业务对象>协议文档.md
<业务对象>对接指南.md
<业务对象>测试方案.md
<业务对象>验收用例.md
<业务对象>时序图.md
```

版本、状态和确认日期应写入文档头部，不写入文件名。推荐状态：

```text
草稿 -> 评审中 -> 已批准 -> 实施中 -> 已废止
```
