## 1. 服务边界

Control Service 提供 `/api/control/**` 和 `/ws/control`，负责管理端设备档案与运行时状态合并、控制会话、视频编排、MQTT 指令/状态桥接。它不承载媒体流，视频会话、LiveKit Token 和文件存储由 Media Service 提供。

生产入口、可信 Header 和时间格式见[Java 服务接口通用约定](../公共约定/Java服务接口通用约定.md)。

## 2. 机器人注册与控制接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/control/robots/registry` | 查询 Control 内存注册表，返回 `{records,total}`；供 BFF 聚合，不是管理端主数据列表 |
| `GET` | `/api/control/robots/{robotId}/control-profile` | 查询管理端档案、能力和当前运行时状态合并后的控制画像 |
| `POST` | `/api/control/robots/{robotId}/control-sessions/acquire` | 申请 30 秒排他控制租约；同一 `clientId` 重复申请会续期 |
| `POST` | `/api/control/robots/{robotId}/control-sessions/takeover` | 校验 `observedStateSeq` 后申请本体控制权并发布手动模式切换 |
| `POST` | `/api/control/robots/{robotId}/control-mode` | 在已有本体控制会话内切换模式 |
| `POST` | `/api/control/robots/{robotId}/control-sessions/{controlSessionId}/release` | 释放控制会话 |
| `POST` | `/api/control/robots/{robotId}/commands/confirm-token` | 生成 30 秒确认 Token 信息；当前代码尚未在普通命令入口校验该 Token |
| `POST` | `/api/control/robots/{robotId}/commands` | 校验控制画像中的有效 action、构造参数并发布设备控制 MQTT |

`GET /api/control/robots` 不存在。大屏设备列表使用 `/api/bigscreen/panorama/overview`。

### 2.1 控制会话语义

- 冲突判断以同一机器人、活跃会话和 `deviceIds` 交集为准。
- 冲突且属于其他终端时，接口当前返回普通响应体 `{code:"CONTROL_LOCKED", holder:...}`，不是 HTTP 409。
- `drive.velocity` 必须：机器人在线、控制模式为手动、会话属于当前 `userId + clientId` 且包含 `base`。
- 合法移动控制会自动把租约续到当前时间后 30 秒；服务没有独立控制心跳接口。
- `takeover` 和 `control-mode` 只发布模式切换请求，最终模式以机器人后续状态上报为准。

### 2.2 通用控制命令

```json
{
  "controlSessionId": "tc_xxx",
  "target": {
    "deviceId": "base",
    "deviceType": "WHEELED_BASE"
  },
  "action": "drive.velocity",
  "params": {
    "linearX": 0.4,
    "linearY": 0,
    "angularZ": 0.2
  },
  "client": {"seq": 12}
}
```

服务端先把 Management `components[].capabilities[].actions` 映射为协议 action。若一个组件没有任何可识别的映射结果，当前代码会按已知 `deviceType` 使用生产兼容动作表；因此“控制画像中出现 action”不一定代表 Management 已逐项登记。请求 action 必须包含在控制画像最终返回的 `devices[].actions` 中，否则返回 `400 INVALID_CONTROL_REQUEST`。`client.seq` 进入 MQTT `seq`，Control 返回的 `commandId` 是发布结果标识，当前不持久化命令也不等待 ACK。

兼容动作表只补充已联调的命令能力，不会伪造在线、音量、灯光或弹筒等运行状态。新增设备类型或新增动作必须在 Management 登记并补充映射，不能依赖兼容表自动放行。

MQTT Topic 按设备类型路由：

```text
robot/{robotId}/control/body/command
robot/{robotId}/control/ptz/command
robot/{robotId}/control/audio/command
robot/{robotId}/control/launcher/command
robot/{robotId}/control/net-gun/command
robot/{robotId}/control/warning-light/command
robot/{robotId}/control/vehicle-light/command
robot/{robotId}/control/multi-function/command
```

完整 action/params 和状态载荷见[客户端事件与载荷协议文档](../客户端事件/客户端事件与载荷协议文档.md)。

## 3. 多合一设备接口

普通多合一动作仍调用通用 `/commands`。当前 Control 为 `MULTI_FUNCTION_BROADCASTER` 明确支持：

```text
set_volume
start_broadcast / stop_broadcast
start_monitor / stop_monitor
set_monitor_suppressed
play_tts / stop_tts
list_audio_files
play_audio_file / stop_audio_file / delete_audio_file
play_alarm / stop_alarm
light.set
set_speaker_tilt / set_light_tilt
```

服务端会按 `controlProfile` 限制音量、TTS 最大长度与 voice、灯光模式、两个俯仰百分比等参数。`start_broadcast/stop_broadcast/start_monitor/stop_monitor` 必须携带 `mediaSessionId`。

音频文件先上传到 Media Service，再调用：

```http
POST /api/control/robots/{robotId}/devices/{deviceId}/audio-file-transfers
Content-Type: application/json

{"fileId":"file_xxx"}
```

约束：当前用户必须有 `EQUIPMENT_OPERATOR`；文件必须为 `AUDIO + READY`，归属同一 `robotId/deviceId`，大小 `0 < size <= 20MB`，文件名无路径且扩展名为 `.mp3` 或 `.wav`。成功后发布 `audio_file_transfer` 到 `robot/{robotId}/control/multi-function/command`，响应包含 `transferId`、文件元数据和 MQTT 发布结果。

## 4. 实时视频接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/control/robots/{robotId}/cameras/{deviceId}/video/start` | 启动/复用机器人摄像头视频 |
| `POST` | `/api/control/robots/{robotId}/cameras/{deviceId}/video/intercom/start` | 从摄像头入口启动对讲 |
| `POST` | `/api/control/fixed-cameras/{cameraId}/video/start` | 启动/复用单路固定摄像头 |
| `POST` | `/api/control/fixed-cameras/video/start` | 批量启动固定摄像头，返回 `sessions` 与 `failures` |
| `GET` | `/api/control/video-sessions` | 当前用户最近 20 条会话 |
| `GET` | `/api/control/video-sessions/active` | 最多 16 条可复用会话 |
| `GET` | `/api/control/video-sessions/{sessionId}` | 会话详情 |
| `GET` | `/api/control/video-sessions/{sessionId}/tracks` | Track 记录 |
| `POST` | `/api/control/video-sessions/{sessionId}/token` | 签发 viewer Token |
| `POST` | `/api/control/video-sessions/{sessionId}/heartbeat` | 刷新当前 viewer 心跳 |
| `POST` | `/api/control/video-sessions/{sessionId}/stop` | 当前 viewer 离开；最后一人离开后进入空闲等待 |
| `POST` | `/api/control/video-sessions/{sessionId}/restart` | 重新生成并下发 start command |
| `POST` | `/api/control/video-sessions/{sessionId}/switch-channel` | 更新通道/清晰度并重新推流 |
| `POST` | `/api/control/video-sessions/{sessionId}/intercom/start` | 在已有会话启动对讲 |
| `POST` | `/api/control/video-sessions/{sessionId}/intercom/token` | 重签操作员对讲 Token |
| `POST` | `/api/control/video-sessions/{sessionId}/intercom/heartbeat` | 对讲占用心跳 |
| `POST` | `/api/control/video-sessions/{sessionId}/intercom/stop` | 停止对讲，不一定关闭视频 |
| `POST` | `/api/control/video-sessions/{sessionId}/recordings/start` | 开始 LiveKit Egress 录像 |
| `POST` | `/api/control/video-sessions/{sessionId}/recordings/{fileId}/stop` | 停止录像 |
| `GET` | `/api/control/video-sessions/{sessionId}/recordings/active` | 查询当前活动录像 |

请求字段、响应模型、状态机和 MQTT 载荷见[实时视频接口与协议文档](../实时视频/实时视频接口与协议文档.md)。

固定摄像头只允许 `visible` 通道。Control 先查询管理端摄像头列表并校验 `enabled` 与码流；请求 `sub/main` 不存在时自动回退到另一条可用码流。首次 start command 会携带选中的内部 `rtspUrl` 给 Gateway；手工重启、自动恢复和切换命令可能不含该字段，Gateway 会按摄像头 ID 回查 Management。Gateway ID 由 `control.mqtt.fixed-camera-gateway-id` 配置。`rtspUrl` 与 publisher Token 均不得返回浏览器；当前 MQTT 发布日志仍会记录完整载荷，生产前需要脱敏。

## 6. 里程统计接口

```http
GET /api/control/statistics/mileage?startTime=2026-08-14%2000:00:00&endTime=2026-08-14%2023:59:59&robotIds=test111
```

`robotIds` 可重复传入；不传表示查询全部机器人。时间格式为
`yyyy-MM-dd HH:mm:ss`，区间首尾均包含。响应原始单位为米：

```json
{
  "startTime": "2026-08-14 00:00:00",
  "endTime": "2026-08-14 23:59:59",
  "totalMeters": 1256.800,
  "unit": "m",
  "hasData": true,
  "byRobot": [
    {"robotId": "test111", "mileageMeters": 1256.800}
  ]
}
```

`hasData` 表示查询设备存在采集基线，不等同于区间内一定发生移动。首条读数仅
建立基线，统计采用有效相邻增量，并排除重复、乱序和异常速度跳变。

## 7. WebSocket

Control 在 `/ws/control` 和兼容路径 `/ws/media` 注册同一 Handler。服务端广播事件使用：

```json
{
  "event": "robot.state",
  "timestamp": "2026-08-12 21:30:00",
  "data": {}
}
```

浏览器可发送请求型消息：

```json
{
  "type": "control.command",
  "requestId": "req-1",
  "payload": {}
}
```

当前支持 `control.command`、`video.intercom.call.accept`、`video.intercom.call.reject`、`video.intercom.call.query`；未知 type 为前向兼容而静默忽略。请求型响应使用 `{type,requestId,timestamp,payload}`，广播型事件使用 `{event,timestamp,data}`，两种 envelope 不应混淆。

Control 还可订阅上游 STOMP `/topic/platform/realtime-events`。只接受 `type=task.changed.v1` 且 scopes 含 `PLAN` 或 `EXECUTION` 的事件，按 `source:id` 去重后广播 `management.task.invalidated`；它是失效通知，不携带权威任务快照。
