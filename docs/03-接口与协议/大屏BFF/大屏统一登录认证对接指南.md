# 大屏统一登录认证对接指南

## 1. 认证方式

大屏使用管理端现有 Keycloak，采用 OAuth2/OIDC Authorization Code + PKCE(S256) 流程：

1. 浏览器访问大屏，前端发现未登录；
2. 跳转到 Keycloak 登录页；
3. 登录成功后携带授权码返回原大屏路径；
4. 前端用授权码换取 Access Token；
5. HTTP 请求统一访问 `/api-gw/**`，并使用 `Authorization: Bearer <access_token>`；
6. `/ws/bigscreen` 握手使用查询参数 `access_token=<access_token>`；
7. 大屏 Nginx 将 HTTP `/api-gw/**` 请求转发到管理端 API Gateway；
8. 大屏 Nginx 将 WebSocket `/ws/bigscreen` 直接转发到 BFF，由 BFF 校验 Token。

Access Token 仅由 Keycloak JavaScript 适配器保存在页面内存中，不写入 Cookie 或持久化存储。

## 2. 管理端配置

管理端需要新增一个公共应用：

| 配置 | 值 |
| --- | --- |
| 模式 | `PUBLIC_SPA` |
| Client ID | `bigscreen-web` |
| Flow | Authorization Code |
| PKCE | `S256` |
| Implicit Flow | 关闭 |
| Redirect URIs | `https://192.168.124.234:4443/*` |
| Web Origins | `https://192.168.124.234:4443` |

用户按实际操作权限分配以下客户端角色：

| 角色 | 用途 |
| --- | --- |
| `MEDIA_VIEWER` | 查看实时视频 |
| `MEDIA_OPERATOR` | 视频会话和语音对讲操作 |
| `EQUIPMENT_OPERATOR` | 机器人及上装设备控制 |

## 3. 大屏前端配置

生产部署修改 `robot-ui/public/js/auth-config.js`：

```js
window.__BIGSCREEN_AUTH_CONFIG__ = {
  keycloakUrl: 'https://192.168.124.235:18443',
  keycloakRealm: 'iam-auth',
  keycloakClientId: 'bigscreen-web',
  keycloakLocale: 'zh-CN'
}
```

也可在构建时使用：

```bash
export VUE_APP_KEYCLOAK_URL='https://192.168.124.235:18443'
export VUE_APP_KEYCLOAK_REALM='iam-auth'
export VUE_APP_KEYCLOAK_CLIENT_ID='bigscreen-web'
export VUE_APP_BASE_API='/api-gw'
```

## 4. 大屏 Nginx 配置

大屏 Nginx 将 `/api-gw/` 转发到 `192.168.124.235:8080`，转发时会剥离
`/api-gw`。`/ws/bigscreen` 直接转发到 BFF，避免管理端 API Gateway 参与
WebSocket 协议转发；BFF 使用查询参数中的 `access_token` 完成认证。配置见
`deploy/nginx/robot-mediaserver.conf`。

录像 HLS 播放路径以 `/api-gw/api/bigscreen/control/files/{fileId}/hls/**` 暴露，但由 Nginx
直接回源 BFF，并使用播放接口签发的短期 `token` 校验。该路径不使用 Keycloak
Bearer Token，因为浏览器原生媒体请求无法稳定附加 Authorization Header。

## 5. API Gateway 路由

管理端 API Gateway 只需提供大屏 REST 路由：

```yaml
- id: bigscreen-bff-api
  uri: http://192.168.124.234:8090
  predicates:
    - Path=/api/bigscreen,/api/bigscreen/**

```

控制与媒体请求统一使用 `/api/bigscreen/control/**`，由 BFF 转换为内部
`/api/control/**` 后转发。API Gateway 还需要允许来源
`https://192.168.124.234:4443`。

## 6. BFF 配置

```bash
export BIGSCREEN_AUTH_CLIENT_ID='bigscreen-web'
export BIGSCREEN_AUTH_ISSUER_URI='https://192.168.124.235:18443/realms/iam-auth'
export BIGSCREEN_AUTH_JWK_SET_URI='http://192.168.124.235:18080/realms/iam-auth/protocol/openid-connect/certs'
```

如果 Keycloak 使用内部 CA 或自签证书，BFF 所在 JVM 必须信任该 CA；也可以将
`BIGSCREEN_AUTH_JWK_SET_URI` 配置为 BFF 可访问的 Keycloak 内部 HTTP 地址。
`issuer-uri` 仍应与 Token 中的 `iss` 完全一致。
BFF 验签支持管理端当前使用的 `ES256`，同时兼容 `RS256`。

公网部署时，`BIGSCREEN_AUTH_ISSUER_URI` 必须使用 Keycloak 签发 Token 时的公网
地址；`BIGSCREEN_AUTH_JWK_SET_URI` 可继续使用 BFF 可访问的内网 HTTP 地址。例如：

```bash
export BIGSCREEN_AUTH_ISSUER_URI='https://175.155.35.79:18443/realms/iam-auth'
export BIGSCREEN_AUTH_JWK_SET_URI='http://192.168.124.235:18080/realms/iam-auth/protocol/openid-connect/certs'
```

## 7. 验证

1. 清除大屏旧页面会话后访问任意大屏路径，应跳转到 Keycloak；
2. 登录后应返回原路径，地址栏不保留 `code`、`state`；
3. 大屏 HTTP 请求路径应以 `/api-gw/` 开头并包含 Bearer Token；
4. 不带 Token 请求 `/api-gw/api/**` 应返回 `401`；
5. `/ws/bigscreen` 应携带 `access_token` 并成功完成握手，连接应持续保持；
6. `/api-gw/api/bigscreen/panorama/overview` 应由网关转发 BFF 并返回 `200`；
7. Token 过期前前端应自动刷新，刷新失败时重新进入统一登录。
