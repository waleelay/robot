## 1. 服务边界

Media Service 负责视频会话、LiveKit Room/Token、Track、viewer、对讲占用、LiveKit Egress 录像、通用文件和 TTS。它不向机器人发布 MQTT；内部视频接口返回 command，由 Control Service 选择机器人或固定摄像头 Gateway Topic 下发。

生产信任边界、时间和错误响应见[Java 服务接口通用约定](../公共约定/Java服务接口通用约定.md)。

## 2. 视频内部接口

基础路径：`/internal/media/video-sessions`。

### 2.1 面向 Control 的业务接口

| 方法 | 相对路径 | 说明 |
| --- | --- | --- |
| `POST` | `/` | 创建或按源/设备/通道/清晰度复用会话，并登记 viewer |
| `POST` | `/intercom` | 创建/复用对讲 Room 容器，不登记 viewer |
| `GET` | `/` | 当前用户最近 20 条会话 |
| `GET` | `/active` | 可复用会话，最多 16 条 |
| `GET` | `/{sessionId}` | 会话详情并为当前身份签发 viewer Token；当前未校验会话组织归属 |
| `GET` | `/{sessionId}/tracks` | Track 记录；当前未校验用户或组织归属 |
| `POST` | `/{sessionId}/token` | viewer Token |
| `POST` | `/{sessionId}/heartbeat` | viewer 心跳 |
| `POST` | `/{sessionId}/stop` | 当前 viewer 离开 |
| `POST` | `/{sessionId}/restart` | 仅更新会话状态；对外重启通常使用 `restart-command` |
| `POST` | `/{sessionId}/switch-channel` | 更新通道/清晰度 |
| `POST/GET` | `/{sessionId}/recordings/**` | LiveKit Egress 录像；启动前解析房间真实视频 Track SID，停止操作支持 Egress 已结束时的幂等收敛 |

### 2.2 命令生成与调度接口

| 方法 | 相对路径 | 调用方/语义 |
| --- | --- | --- |
| `POST` | `/{sessionId}/client-start?event=...` | 确保 Room、签发 publisher Token、置 `REQUESTING_CLIENT` 并返回 `VideoStartCommand`；viewerCount=0 时返回空 |
| `POST` | `/{sessionId}/start-command` | 基于当前会话重签 publisher Token，不改变状态 |
| `POST` | `/{sessionId}/restart-command` | 重建 Room/command 并返回命令 |
| `POST` | `/online-restart-commands?robotId=&status=` | 机器人从离线变在线时，为仍有 viewer 的最新会话生成恢复命令 |
| `GET` | `/interrupted-restart-candidates?before=` | Control 调度器查询中断恢复候选 |
| `GET` | `/idle-release-candidates?before=` | 查询空闲释放候选 |
| `POST` | `/{sessionId}/release-idle` | 关闭 Room/Track 并返回 stop payload；无需释放时返回 `{}` |
| `GET` | `/intercom-timeout-candidates?before=` | 查询对讲心跳超时候选 |

### 2.3 机器人状态回写

| 方法 | 相对路径 | 说明 |
| --- | --- | --- |
| `POST` | `/status` | 接收 Control 转发的视频状态 |
| `POST` | `/intercom/status` | 接收对讲状态 |
| `POST` | `/{sessionId}/intercom/start` | 占用对讲并签发操作员 Token |
| `POST` | `/{sessionId}/intercom/token` | 对当前持有者重签 Token |
| `POST` | `/{sessionId}/intercom/heartbeat` | 刷新占用心跳 |
| `POST` | `/{sessionId}/intercom/stop` | 释放对讲持有者 |
| `POST` | `/{sessionId}/intercom/expire` | 超时失效并返回机器人 stop payload |
| `POST` | `/{sessionId}/intercom/start-command` | 签发机器人音频发布/订阅 Token |

完整字段、状态转移和 MQTT 映射见[实时视频接口与协议文档](../实时视频/实时视频接口与协议文档.md)。

## 3. 视频模型关键语义

创建请求：

| 字段 | 必填 | 当前语义 |
| --- | ---: | --- |
| `robotId` | 是 | 机器人源为机器人 ID；固定摄像头当前为了兼容非空约束也传 `cameraId`，业务判断必须看 `sourceType/sourceId` |
| `sourceType` | 否 | 默认 `ROBOT_CAMERA`；另有 `FIXED_CAMERA` |
| `sourceId` | 否 | 缺省回退到 `robotId` |
| `deviceId` | 是 | 摄像头/视频源路由 ID |
| `channel` | 是 | `visible/thermal/fusion` |
| `quality` | 否 | 默认 `sub`；另有 `main/auto` |
| `reuse` | 否 | 默认 `false`；为 true 时按 `sourceType+sourceId+deviceId+channel+quality` 查找 `ROOM_READY/STREAMING/IDLE_WAIT` |
| `clientRequestId` | 否 | 当前只透传到 DTO，未参与持久化或幂等判断 |

`VideoSessionResponse` 还包含对讲字段：`intercomStatus`、`intercomAudioOnly`、`intercomOperatorId`、`intercomClientId`、`robotAudioTrackSid`、`robotAudioTrackName`。不要用视频 `status` 推断对讲状态；两套状态机相互独立。

当前授权缺口：`reuse=true` 的复用查询、`GET /active`、按 ID 查询、Track 查询及若干内部命令接口没有按 `orgId/userId` 隔离；`GET /` 仅按 `createdBy=userId` 取最近 20 条，也没有同时限定组织。在生产多租户环境补齐服务端授权前，必须依赖受控入口和网络隔离，调用方不能把“拿到 sessionId”视为已获得该会话权限。

## 4. 文件接口

`FileController` 同时注册两个等价基础路径：

```text
/api/media/files
/internal/media/files
```

前者主要供机器人直传，后者供 Control 代理。两者提供简单上传、multipart、状态、列表、详情、扩展绑定、单个/批量删除、下载、正文和 HLS 播放。详细定义见[通用文件服务接口文档](../文件服务/通用文件服务接口文档.md)。

可信机器人网段过滤器只在 `media.file.trusted-robot-network-enabled=true` 时生效，且只保护 `/api/media/files/multipart-uploads**` 和 `/api/media/files/{fileId}/status`；它读取 TCP 对端地址，不信任 `X-Forwarded-For`。

## 5. TTS 接口

### 5.1 生成并下载文件

```http
GET /api/media/tts/generate-file?text=巡检开始
X-Robot-Id: robot-001
```

成功返回音频二进制，`Content-Type` 为 `audio/wav`、`audio/mpeg` 或 `application/octet-stream`，并返回 `X-TTS-Cache-Hit: true|false`。缓存键为 `text + voice + format` 的 SHA-256；本地输出目录按安全化后的 robot ID 分隔。

### 5.2 生成并推送到 Media WebSocket

```http
GET /api/media/tts/generate-and-play?text=巡检开始
X-Robot-Id: robot-001
```

接口成功返回空正文。服务先广播文本事件：

```json
{
  "event": "tts.audio.meta",
  "timestamp": "2026-08-12 21:30:00",
  "data": {
    "robotId": "robot-001",
    "filename": "hash.wav",
    "format": "wav",
    "sampleRate": 22050,
    "channels": 1,
    "bitsPerSample": 16,
    "encoding": "PCM_SIGNED",
    "cacheHit": false
  }
}
```

随后向 `/ws/media` 的所有连接广播二进制音频。WAV 时当前代码按 `media.tts.wav-header-offset`（默认 44 字节）剥离头部；这不是按 robotId 定向推送，调用方必须根据前一条 meta 事件自行关联。生成前会移除 `！!。?？`，文本不能为空且不得超过 `media.tts.max-text-length`。

Media TTS 与多合一设备 `play_tts` 不是同一链路：前者调用 OpenTTS 并向 Media WebSocket 推音频；后者由 Control 直接下发文本/voice 给机器人多合一设备驱动。

## 6. Media WebSocket

Media Service 只注册 `/ws/media`。它发送广播 envelope `{event,timestamp,data}` 和 TTS 二进制帧，不处理浏览器文本控制消息。面向大屏的生产连接通常通过 BFF/Control 的 `/ws/control`，Media `/ws/media` 主要用于内部调试和 TTS 二进制流。
