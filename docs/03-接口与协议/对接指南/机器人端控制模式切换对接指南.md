# 机器人端控制模式切换对接指南

## 1. 对接范围

本文档供机器人端 Codex 直接按照实现。

### 机器人端需要改动

1. 在现有 MQTT 命令分发器中处理 `control.mode.set`。
2. 对接底盘或导航系统，完成手动/导航控制权切换。
3. 模式真实生效后立即上报 `controlMode`。
4. 根据当前模式限制人工速度指令的执行。

### 平台已实现，机器人端无需改动

- 大屏申请控制会话并发起模式切换。
- Control Service 校验权限、会话和机器人状态。
- Control Service 发布 MQTT 命令，消费机器人状态并通知大屏。

机器人端不需要新增 REST 接口。

## 2. 接收模式切换命令

复用机器人端现有 MQTT 连接和命令订阅：

| 项 | 值 |
| --- | --- |
| Topic | `robot/{robotId}/control/body/command` |
| QoS | `1` |
| action | `control.mode.set` |
| 目标设备 | `target.deviceId=base` |

命令示例：

```json
{
  "robotId": "sx-songling-001",
  "seq": 1289,
  "target": {
    "deviceId": "base",
    "deviceType": "WHEELED_BASE"
  },
  "action": "control.mode.set",
  "params": {
    "controlMode": "手动模式"
  },
  "issuedAt": "2026-09-13T14:30:00+08:00"
}
```

`params.controlMode` 只允许：

| 值 | 含义 |
| --- | --- |
| `手动模式` | 人工遥操控制底盘 |
| `导航模式` | 导航或自动任务控制底盘 |

未知值、错误 `robotId` 或非 `base` 目标必须拒绝执行并记录原因，不要自行转换为本地默认模式。

## 3. 机器人端处理逻辑

### 切换到手动模式

1. 停止导航系统对底盘的速度输出。
2. 发送零速度并完成安全停车。
3. 将底盘控制权切换到人工遥操通道。
4. 从底盘或控制器确认已切换成功。
5. 立即上报 `controlMode=手动模式`。

真实切换成功前不得执行 `drive.velocity`。

### 切换到导航模式

1. 停止人工速度输出并发送零速度。
2. 清理未执行的遥操速度指令。
3. 将底盘控制权切换到导航通道。
4. 从底盘或控制器确认已切换成功。
5. 立即上报 `controlMode=导航模式`。

切换模式不得自动启动、暂停、恢复或终止任务。

### 异常与重复命令

- MQTT QoS 1 可能重复投递；相同目标模式必须幂等处理。
- 模式切换必须串行，不得同时操作两个控制通道。
- 切换失败时安全停车，保留并上报最后一个真实模式。
- 不得在收到命令时直接把命令参数当成已生效状态。

## 4. 上报真实模式

复用机器人现有设备状态上报：

| 项 | 值 |
| --- | --- |
| Topic | `eiop/v1/edge/{serialNumber}/status` |
| QoS | `1` |
| messageType | `DEVICE_STATUS_REPORT` |
| 状态字段 | `payload.status.control.controlMode` |

`{serialNumber}` 必须与命令 Topic 中的 `{robotId}` 一致。将 `control` 合并到机器人端现有状态报文中，不要为模式切换伪造其他状态字段。

```json
{
  "messageId": "status-20260913-000128",
  "messageType": "DEVICE_STATUS_REPORT",
  "schemaVersion": "1.0",
  "timestamp": "2026-09-13T14:30:00.350+08:00",
  "payload": {
    "status": {
      "control": {
        "controlMode": "手动模式"
      }
    }
  }
}
```

机器人端必须在以下时机上报真实模式：

- MQTT 连接或重连成功后。
- `control.mode.set` 真实执行成功后立即上报。
- 周期状态心跳。
- 本地遥控器或安全系统改变模式后。

## 5. 完成标准

- [ ] 能收到并解析 `control.mode.set`。
- [ ] `手动模式` 与 `导航模式` 均能切换真实底盘控制权。
- [ ] 切换期间不会同时输出导航和人工速度。
- [ ] 切换成功后立即上报真实 `controlMode`，大屏无需刷新即可更新。
- [ ] 重复命令不会导致重复启停或状态翻转。
- [ ] 切换失败时不会上报伪造的目标模式。
- [ ] MQTT 重连后恢复命令订阅并立即上报当前模式。

平台返回 `PUBLISHED` 只表示 MQTT 命令已发布。平台将机器人后续上报的 `controlMode` 作为切换成功的最终依据。

完整状态报文定义参见[客户端事件与载荷协议文档](../客户端事件/客户端事件与载荷协议文档.md)。
