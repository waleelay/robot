# 大屏充电与停靠导航对接指南

| 文档属性 | 内容 |
| --- | --- |
| 文档状态 | 已批准（实施基线） |
| 确认日期 | 2026-09-07 |
| 上游文档版本 | 2026-09-07 17:06 收到的《EIOP 充电点与停靠点导航对接指南》 |
| 代码状态 | 本地开发完成，待联调、待上线验证 |
| 适用范围 | `robot-ui`、Bigscreen BFF、Control Service 与 EIOP Management/Control 对接 |

本文定义大屏地图设备弹窗中“一键充电”“前往停靠点”“退出充电桩”的正式版对接方式，以及旧“一键返航/退出充电”入口的清理边界。

本文是本仓库的实施与验收基线；本地代码已完成，不表示已经联调或部署。EIOP 服务点导航的 HTTP 契约来源于管理端提供的新版对接指南；机器人本体离散命令沿用[具身智能装备统一控制一期设计说明书](../../02-设计/统一控制/具身智能装备统一控制一期设计说明书.md)和[控制服务接口文档](../统一控制/控制服务接口文档.md)。

## 1. 最终确认结论

1. 地图设备信息弹窗将原“一键返航”“退出充电桩”调整为“一键充电”“前往停靠点”“退出充电桩”。
2. “一键充电”和“前往停靠点”调用 EIOP Management 的服务点导航接口。
3. “退出充电桩”不调用 EIOP Remote Control 接口，使用本项目 Control Service 的机器人本体低频命令，向 `robot/{robotId}/control/body/command` 单次发布 `docking.leave`。
4. 大屏只负责提交，不订阅 `/topic/tasks/{taskInstanceId}/events`，不展示导航进度、到达终态或失败原因。
5. 大屏不订阅 EIOP `/topic/device-realtime-statuses`。按钮状态复用本项目 Control 已有的 `eiop/v1/edge/+/status` MQTT 状态链路，避免双源竞态。
6. 大屏不订阅 EIOP `/topic/service-point-states`，也不展示服务点实时预占、占用或充电状态；可用性在点击“前往停靠点”时通过候选接口查询。
7. 本功能不扩展现有 Management STOMP 桥接。
8. 设备运行状态直接补充到现有大屏设备模型，不创建第二套大屏运行态对象。
9. 所有 HTTP 请求按当前登录用户的组织、设备和业务权限校验。前端按钮状态不是权限或安全边界。
10. 其他远程控制面板中的旧“一键返航/退出充电”均未形成有效执行链路，按废弃功能移除；新三个入口不放入手动远程控制面板。

## 2. 系统边界

正式环境调用链如下：

```text
robot-ui
  ├─ HTTP ──> Bigscreen BFF ──> EIOP Management
  │                              ├─ 查询停靠点候选
  │                              └─ 创建充电/停靠导航
  ├─ HTTP ──> Bigscreen BFF ──> 本项目 Control Service
  │                              ├─ 查询本体控制画像
  │                              ├─ 申请/释放本体控制会话
  │                              └─ 发布 docking.leave
  └─ WS ────> Bigscreen BFF <── 本项目 Control Service
                                  └─ 发布现有 robot.state 增量

边缘端 ── eiop/v1/edge/{serialNumber}/status ──> MQTT
                                                  ├─> EIOP Control
                                                  └─> 本项目 Control Service

EIOP Management ──> EIOP Control ──> 边缘端任务执行
本项目 Control Service ── robot/{robotId}/control/body/command ──> 机器人客户端
```

生产环境中浏览器只访问 Bigscreen BFF 所在源站，不直连 EIOP Management、EIOP Control 或本项目 Control Service。BFF 转发当前登录身份；下游继续执行资源、能力和状态校验。

| 模块 | 本功能职责 |
| --- | --- |
| `robot-ui` | 展示按钮和停靠点候选，执行前端状态判断，提交请求，处理提交级提示 |
| `bigscreen-bff` | 统一认证入口、HTTP 转发/聚合、现有设备模型补充、现有 WebSocket 事件适配 |
| 本项目 `control-service` | 处理现有边缘状态 MQTT；校验控制会话、权限、能力和状态；发布 `docking.leave` |
| EIOP Management | 候选点查询、原子预占、一次性导航创建、组织/设备/地图/任务权限 |
| EIOP Control | 设备实时状态、任务包下发和服务点状态闭环 |
| 边缘端/机器人 | 执行服务点导航或驶离动作，持续上报定位、任务和充电事实 |

## 3. 标识与运行状态

### 3.1 `robotId`、`serialNumber` 和 `mapId`

本仓库大屏模型继续使用 `robotId`。对接 EIOP 时：

```text
robotId = Management 设备 serialNumber
```

不使用数据库内部设备主键替代 `serialNumber`。

| 场景 | `mapId` 含义 | 类型 |
| --- | --- | --- |
| Management 地图、点位接口 | 平台地图 ID | Long/数字字符串 |
| `status.localization.mapId` | 设备侧地图 ID | String |
| 平台地图 `edgeMapId` | 平台地图与设备侧地图的关联值 | String |

设备发起导航时，由 EIOP 按 `status.localization.mapId == map.edgeMapId` 解析平台地图。前端不得混用两类 ID，也不得使用 `mapPointId` 代替服务点 `pointCode`。

### 3.2 状态唯一来源

本项目 Control 已订阅 `eiop/v1/edge/+/status`。正式实现继续沿用：

```text
DEVICE_STATUS_REPORT
  -> EdgeDeviceStatusHandler
  -> EquipmentControlService / RobotRegistryService
  -> robot.state
  -> Bigscreen BFF panorama.device.status.changed / location.changed
  -> robot-ui Store
```

不得再用 EIOP 设备状态 STOMP 更新同一组字段。否则 MQTT 和 STOMP 的消息延迟、重连与顺序不同，可能由旧事件覆盖新状态。

### 3.3 大屏设备模型新增字段

在 `/api/bigscreen/panorama/overview` 的现有 `devices[]` 项上直接增加：

```json
{
  "robotId": "SN007",
  "status": "online",
  "runtimeUpdatedAt": "2026-09-07T10:00:01Z",
  "charging": false,
  "chargingStatus": "NOT_CHARGING",
  "taskStatus": "IDLE",
  "edgeLocation": {
    "localized": true,
    "mapId": "edge-map-factory-a",
    "x": 12.3,
    "y": -3.0,
    "z": 0,
    "yaw": 1.2,
    "updatedAt": "2026-09-07T10:00:01Z"
  },
  "location": {
    "localized": true,
    "mapId": "edge-map-factory-a",
    "x": 12.3,
    "y": -3.0,
    "z": 0,
    "yaw": 1.2,
    "updatedAt": "2026-09-07T10:00:01Z"
  }
}
```

| 字段 | 来源和规则 |
| --- | --- |
| `status` | 继续使用本项目 Control 的 `online/fault/offline` 口径 |
| `runtimeUpdatedAt` | 最后一次被本项目 Control 接受的边缘状态时间，用于 30 秒新鲜度判断 |
| `charging` | `status.energy.charging`，必须保留 `true/false/null` 三态 |
| `chargingStatus` | 仅展示和诊断，不代替 `charging` 做判断 |
| `taskStatus` | `status.task.taskStatus` 归一化后的值；本功能只接受明确的 `IDLE` |
| `edgeLocation.localized` | 标准定位结果，必须保留 `true/false/null` 三态 |
| `edgeLocation.mapId/x/y` | 服务点导航前置条件，保留设备侧地图 ID，不用 GIS 经纬度替代 |
| `location` | 保留既有地图展示语义；其中 `mapId` 仍可能被任务的平台地图 ID 覆盖，不用于服务点导航准入 |

未知、缺失、无法解析或相互矛盾的字段按不可执行处理。Control、BFF 和前端不得把缺失的 `charging`、`localized` 或 `taskStatus` 自动补成可执行值。

## 4. 按钮展示和可执行规则

三个入口只对支持服务点导航的移动机器人展示。固定摄像头、无人机、充电桩等非目标设备不展示。

| 条件 | 一键充电 | 前往停靠点 | 退出充电桩 |
| --- | ---: | ---: | ---: |
| 当前用户拥有设备操作权限 | 必须 | 必须 | 必须 |
| `status=online` | 必须 | 必须 | 必须 |
| `runtimeUpdatedAt` 距当前不超过 30 秒 | 必须 | 必须 | 必须 |
| `taskStatus=IDLE` | 必须 | 必须 | 必须 |
| `charging` 已明确上报 | 必须 | 必须 | 必须 |
| `charging=false` | 必须 | 允许 | 禁止 |
| `charging=true` | 禁止 | **允许** | 必须 |
| `edgeLocation.localized=true` | 必须 | 必须 | 不要求 |
| `edgeLocation.mapId/x/y` 有效 | 必须 | 必须 | 不要求 |
| Management 明确登记 `DEVICE_CONTROL/LEAVE_CHARGER` | 不适用 | 不适用 | 必须 |

补充规则：

- 正在充电且 `taskStatus=IDLE` 时允许“前往停靠点”；机器人通过导航任务自主驶离，不先发送 `docking.leave`。
- 非 `IDLE`、状态过期、字段未知或状态矛盾时禁用按钮并刷新权威设备快照。
- 点击任一入口后，对该设备设置提交互斥锁，三个按钮同时禁用；本次 HTTP 流程结束后释放。
- 提交锁只防止当前请求并发，不表示动作正在执行。POST 和 MQTT 发布结果仍由后端执行最终互斥和状态校验。
- 不可用原因建议按无权限、离线、状态过期、任务非空闲、充电未知、未定位、地图/坐标无效、能力未登记的顺序展示。

## 5. 一键充电

“一键充电”不预查候选点，直接通过 BFF 同源提交：

```http
POST /api/v1/management/external/service-point-navigations
Authorization: Bearer <用户JWT>
Content-Type: application/json

{
  "serialNumber": "SN007",
  "intent": "CHARGE",
  "pointCode": null
}
```

Management 按距离和 `pointCode` 顺序选择并原子预占充电点。大屏不得自行选择充电点。

响应中的 `accepted=true`、`executionStatus=PREPARING` 只表示平台已接受请求。前端提示“充电任务已提交”，不能提示“充电成功”。无候选、状态竞态或点位刚被占用时，以 POST 的 `409000` 为准，不自动重发。

## 6. 前往停靠点

### 6.1 查询候选点

```http
GET /api/v1/management/external/devices/{serialNumber}/service-point-options?intent=STANDBY
Authorization: Bearer <用户JWT>
```

候选项至少包含 `pointCode`、`pointName`、`pointType=STANDBY`、`coordinateX/Y/Z` 和 `headingYaw`。

### 6.2 二级选择规则

| 可用候选数 | 大屏行为 |
| ---: | --- |
| 0 | 不发起导航，提示“当前没有可用停靠点” |
| 1 | 不弹二级列表，直接使用唯一候选的 `pointCode` 提交 |
| 大于 1 | 二级展示全部可用停靠点，由用户选择后提交 |

本项目不使用新版文档提供的 `STANDBY + pointCode=null` 自动选择。这样既保留用户选择能力，也兼容当前 Management 代码在多候选时要求明确 `pointCode` 的行为。

列表使用候选接口返回顺序，不在浏览器重新计算距离。最终可用性仍以 POST 原子预占结果为准。

### 6.3 发起导航

```http
POST /api/v1/management/external/service-point-navigations
Authorization: Bearer <用户JWT>
Content-Type: application/json

{
  "serialNumber": "SN007",
  "intent": "STANDBY",
  "pointCode": "STANDBY-02"
}
```

正在充电的空闲设备允许提交。边缘端接收 `POINT + pointContext.pointType=STANDBY` 后自主完成驶离和导航；大屏不得额外发送 `docking.leave`。成功只提示“停靠任务已提交”。

## 7. 退出充电桩

### 7.1 能力判定

Management 设备 Manifest 中机器人本体必须明确登记：

```json
{
  "code": "DEVICE_CONTROL",
  "actions": [
    { "code": "LEAVE_CHARGER" }
  ]
}
```

Control Service 只在上述能力和动作精确匹配时把控制画像映射为 `LEAVE_CHARGER -> docking.leave`。
本功能不识别旧 `DOCKING_LEAVE/DOCKING.LEAVE` 别名，也不依赖本体设备类型兼容表生成
`docking.leave`；未明确登记时隐藏按钮，直接请求同样拒绝。

### 7.2 排他控制会话

退出充电桩复用现有离散低频命令模式，但目标为 `BODY/base`：

```http
POST /api/bigscreen/control/robots/{robotId}/control-sessions/acquire
Content-Type: application/json

{
  "scope": "ROBOT",
  "deviceIds": ["base"],
  "actions": ["docking.leave"],
  "mode": "EXCLUSIVE",
  "reason": "leave_charger",
  "ttlSeconds": 30
}
```

- 不要求机器人切换到手动模式。
- 与其他终端持有的 `base` 会话冲突时返回 `CONTROL_LOCKED`。
- 命令流程结束后在 `finally` 主动释放会话；释放失败只记录告警，不重复下发命令。

### 7.3 单次发布命令

先查询：

```http
GET /api/bigscreen/control/robots/{robotId}/control-profile
```

确认 `BODY/base` 启用、在线且包含 `docking.leave` 后提交：

```http
POST /api/bigscreen/control/robots/{robotId}/commands
Content-Type: application/json

{
  "controlSessionId": "tc_xxx",
  "target": {
    "scope": "BODY",
    "deviceId": "base",
    "deviceType": "WHEELED_BASE"
  },
  "action": "docking.leave",
  "params": {},
  "client": {
    "terminalId": "<当前大屏终端ID>",
    "source": "map_device_popup_leave_charger",
    "seq": 3101,
    "timestamp": "2026-09-07T10:30:30+08:00"
  }
}
```

`deviceType` 取控制画像返回值，不硬编码。BFF 将路径映射到本项目 Control Service 的 `/api/control/robots/{robotId}/...`。

Control Service 单次发布到 `robot/{robotId}/control/body/command`，MQTT `action=docking.leave`、`params={}`。`status=PUBLISHED` 时只提示“退出充电桩指令已发送”。大屏不订阅 `eiop/v1/edge/{serialNumber}/remote-control/results`。

### 7.4 服务端强制校验

Control Service 在申请会话和发布 `docking.leave` 时必须校验：

- 当前身份包含 `EQUIPMENT_OPERATOR`；
- 目标设备在当前用户经 Management 过滤后的授权设备集合内；
- 控制会话属于当前 `userId + clientId`，有效且包含 `base` 和 `docking.leave`；
- 设备在线且最后边缘状态不超过 30 秒；
- `taskStatus=IDLE`；
- 标准充电事实 `charging=true`；
- Management 明确登记 `DEVICE_CONTROL/LEAVE_CHARGER`；
- 本体 `base` 已启用并在线。

任一条件不满足都不得发布 MQTT。前端按钮状态和控制画像缓存不能替代发布时校验。

### 7.5 驶离后的状态闭环

大屏不根据按钮结果释放充电点。EIOP 必须根据后续事实完成对账：

```text
charging 从 true 变为 false
+ 定位状态新鲜且有效
+ 设备已离开原充电点判定范围
=> 释放原充电点活动归属
```

“充电中前往停靠点”还应结合停靠导航成功建立新停靠点状态并释放原充电点。该闭环属于 EIOP Control/Management 的上线前置条件，不由大屏模拟。

## 8. 不接入 EIOP STOMP

新版管理端文档提供三个 Topic，但本项目均不订阅：

| Topic | 不订阅原因 |
| --- | --- |
| `/topic/device-realtime-statuses` | 已有同源边缘 MQTT 状态链；重复接入会产生双源时序竞态 |
| `/topic/service-point-states` | 本需求不展示实时点位占用；候选接口已过滤不可用点 |
| `/topic/tasks/{taskInstanceId}/events` | 产品确认大屏只负责提交，不展示到达、失败或超时终态 |

因此本功能：

- 不修改 `CenterStompTaskEventBridge`；
- 不新增动态任务 Topic 订阅管理；
- 不扩展 BFF WebSocket 地图权限集合；
- 不新增临时导航任务 Store；
- 不触碰现有 `management.task.invalidated -> PanoramaTaskEventRefresher -> panorama.task.changed` 任务链路。

新版响应中的 `taskInstanceId` 可由 BFF 原样返回，但 robot-ui 不解析、不保存、不用于业务判断。

## 9. 权限边界

### 9.1 充电和停靠导航

robot-ui 通过 BFF 同源访问 `/api/v1/management/**`。BFF 验证当前用户 JWT、删除浏览器伪造的可信身份头，并透传真实 Bearer Token和服务端解析的身份上下文。Management 负责组织、设备、地图和任务业务权限。

### 9.2 退出充电桩

本项目 Control 使用当前身份查询 Management 设备列表/详情。只有当前身份可见的 `serialNumber` 才能申请会话和下发命令；缓存必须按身份隔离。`docking.leave` 还明确要求 `EQUIPMENT_OPERATOR`，无操作角色时不展示按钮，绕过 UI 请求也必须拒绝。

## 10. 错误和重试

| 场景 | 大屏行为 |
| --- | --- |
| `400000/400001` 或本地参数错误 | 提示请求无效，不自动重试 |
| `401002` | 进入现有登录刷新/失效流程 |
| `403002`、资源不可见或缺少操作角色 | 提示无权限并刷新授权资源 |
| `404000` | 刷新设备或停靠点候选 |
| `409000` | 提示设备状态或点位已经变化；刷新设备状态/候选 |
| `CONTROL_LOCKED` | 提示本体正在被其他终端控制 |
| `503003` | 提示服务暂不可用，不创建本地模拟任务 |
| 网络超时/断线 | 提示提交结果未知，不盲目自动重发导航或离散命令 |
| `PUBLISHED` | 只提示“指令已发送” |

前端不根据错误文案字符串推断业务分支。

## 11. 前端流程

### 11.1 打开设备弹窗

1. 从现有大屏设备模型读取最新状态。
2. 状态缺失或过期时刷新全景设备快照。
3. 查询控制画像，判断是否明确支持 `docking.leave`。
4. 按第 4 章矩阵计算三个按钮的展示、禁用状态和原因。

### 11.2 点击一键充电

1. 获取设备级提交锁并再次检查本地状态。
2. 直接 POST `intent=CHARGE, pointCode=null`。
3. 提示“充电任务已提交”或服务端错误。
4. 释放提交锁并刷新设备快照。

### 11.3 点击前往停靠点

1. 获取设备级提交锁并再次检查本地状态。
2. 查询 `STANDBY` 候选，按 0/1/多候选规则处理。
3. POST 用户最终选定的 `pointCode`。
4. 提示“停靠任务已提交”或服务端错误。
5. 释放提交锁并刷新设备快照。

### 11.4 点击退出充电桩

1. 获取设备级提交锁并再次检查状态、角色和能力。
2. 申请 `BODY/base` 排他控制会话。
3. 携带 `controlSessionId` 单次 POST `docking.leave`。
4. 收到 `PUBLISHED` 后提示“指令已发送”。
5. 在 `finally` 释放控制会话和提交锁。
6. 后续按钮状态只随真实设备状态更新。

## 13. 新版文档与当前 EIOP 代码差异

### 13.1 开发前代码审计记录

以下问题在正式开发前复核当前仓库代码时发现，必须先记录再整改：

| 编号 | 当前问题 | 风险 | 本次处理边界 |
| --- | --- | --- | --- |
| BIGSCREEN-CHARGE-001 | `EdgeDeviceStatusHandler` 只提升 `chargingStatus`，未提升标准 Boolean `energy.charging` | 无法区分未充电、正在充电与未知，按钮可能误判 | 增加 `charging` 三态透传，不用文本状态反推 |
| BIGSCREEN-CHARGE-002 | Control 在边缘任务状态缺失时为 `missionStatus` 补默认 `IDLE` | 状态未知可能被当作空闲，形成越权执行窗口 | 保留已有兼容字段，但新增正式 `taskStatus` 并对本功能按未知禁用；驶离服务端只接受明确 `IDLE` |
| BIGSCREEN-CHARGE-003 | BFF Overview 的定位仍取 Management 实时状态，且未返回 `localized/yaw` | 与既有 Control MQTT 状态形成双源，按钮和地图可能看到不同版本 | 本功能所需运行态统一取 Control 注册表；保留现有任务摘要读取，不改任务事件链 |
| BIGSCREEN-CHARGE-004 | `robot.state` 的大屏状态适配未携带 `charging/taskStatus`，前端运行态版本保护也未覆盖这些字段和定位 | 首屏后按钮状态不能可靠随设备事实更新，乱序消息可能回退 | 在现有状态事件和现有 Store 合并规则中补齐字段，不新增状态 Store |
| BIGSCREEN-CHARGE-005 | 本体兼容动作默认包含 `docking.leave`，且普通命令校验只强制约束 `drive.velocity` | 未显式登记能力、无排他会话或状态不符时仍可能发布驶离命令 | 从兼容动作移除，新增 `LEAVE_CHARGER` 映射，并对申请会话和发布命令执行专用强校验 |
| BIGSCREEN-CHARGE-006 | 地图弹窗和部分旧控制面板仍展示无执行逻辑的“一键返航/退出充电” | 用户看到可点击但无闭环的入口，并可能误认为已经下发 | 地图弹窗替换为三个正式入口；仅删除已确认无引用或无执行逻辑的旧入口和专用废弃调用链 |
| BIGSCREEN-CHARGE-007 | BFF 会把展示模型 `location.mapId` 改写为任务的平台地图 ID | 直接把该字段改回设备侧地图 ID 会破坏现有 SLAM 地图归属 | 新增同一设备模型内的 `edgeLocation` 保留权威边缘定位；既有 `location` 继续服务地图展示 |
| BIGSCREEN-CHARGE-008 | `robot-ui` 的 `npm run lint` 将整个 `src` 判定为已忽略，命令无法进入代码检查 | 标准模块验收命令不能提供有效 lint 结论 | 本次不扩大范围修改 lint 配置；对改动文件执行显式 ESLint，并以生产构建补充验证 |
| BIGSCREEN-CHARGE-009 | 同一终端已有本体遥控租约时，通用会话申请会直接续期并返回旧租约 | 旧租约不含 `docking.leave` 会使驶离失败；若前端释放复用租约还会中断既有遥控 | `docking.leave` 只复用同一用户终端已有的驶离专用租约，否则创建独立短租约，发布后只释放该租约 |
| BIGSCREEN-CHARGE-010 | 通用会话续期只比较 `clientId`，未确认用户及原租约是否覆盖本次设备和动作 | 登录身份切换或同终端申请不同动作时，可能误复用不属于当前请求的租约 | 续期同时要求 `userId + clientId` 一致且原租约覆盖本次设备和动作；否则同身份创建独立租约、不同身份保持冲突 |
| BIGSCREEN-CHARGE-011 | 服务点请求在快速切换设备并切回后，仅凭 `robotId` 无法区分新旧操作 | 旧候选响应可能覆盖新操作并弹出过期选项 | 弹窗内使用递增操作令牌隔离每次异步流程；失效请求不再更新选项、提示或提交后状态 |

以上整改不改变现有任务事件、人工接管、连续运动、云台、上装设备、媒体或地图路径功能。

### 13.2 管理端新版文档差异

截至本次核对，附件新版文档包含尚未在 `/Users/leelay/Documents/eiop` 当前 `develop` 代码中落地的描述：

| 新版文档描述 | 当前代码 | 本项目处理 |
| --- | --- | --- |
| 导航响应返回 `taskInstanceId` | `ServicePointNavigationResponse/Result` 暂无该字段 | 大屏不订阅任务终态，不依赖该字段 |
| `STANDBY + pointCode=null` 自动选择最近点 | 多候选且未传 `pointCode` 仍返回冲突 | 多候选强制用户选择并传值 |

- 大屏消费 `REMOTE_CONTROL_RESULT_REPORT`。
- 大屏展示服务点 `RESERVED/OCCUPIED/CHARGING` 实时状态。

- 大屏根据坐标自行判定服务点释放、占用或充电成功。
- 在其他手动远程控制面板重复放置三个服务点按钮。

## 15. 验收基线

### 15.1 正常路径

- 空闲、在线、状态新鲜、已定位、未充电设备可直接提交一键充电。
- 停靠点为 0/1/多个时分别执行提示、直接提交、二级选择。
- 空闲且正在充电的设备可提交“前往停靠点”，且不额外发送 `docking.leave`。
- 空闲且正在充电、明确具备 `LEAVE_CHARGER` 的设备可申请排他会话并单次发布 `docking.leave`。
- `PUBLISHED` 只出现“指令已发送”提示，导航 POST 成功只出现“任务已提交”。
- 设备状态始终由现有 MQTT 链路更新，不出现 STOMP 双源覆盖。

### 15.2 禁止路径

- 离线、状态超过 30 秒、任务非 `IDLE` 或状态未知时不能提交三个动作。
- 充电中不能一键充电；未充电不能退出充电桩。
- 未定位或地图/坐标无效时不能提交充电或停靠导航，但不影响满足其他条件的退出充电桩。
- 未明确登记 `DEVICE_CONTROL/LEAVE_CHARGER` 时不显示退出按钮，直接调用接口也必须失败。
- 缺少 `EQUIPMENT_OPERATOR`、设备不在当前授权范围或本体被其他终端控制时不能退出充电桩。
- 一个设备的三个入口不能并发提交。
- 全仓不再出现旧 `/charger/control` 大屏调用链及无效旧按钮。

### 15.3 最小验证命令

```bash
(cd control-service && mvn test)
(cd bigscreen-bff && mvn test)
(cd robot-ui && npm run lint)
(cd robot-ui && npm run build:prod)
```

真实 Management、EIOP Control、MQTT 和机器人行为必须在联调环境补充实际 HTTP、MQTT 发布及状态回流证据；本地单元测试通过不能替代线上链路验证。
