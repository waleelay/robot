## 1. 文档目的与范围

本文档统一定义当前服务端已有能力、业务规则、验证标准与已知缺口，作为设计、联调和验收的需求入口。具体字段和错误码以 [Java 服务接口总览](../../03-接口与协议/Java服务接口总览.md) 及各专项协议为准。

当前需求域：

1. 机器人和固定摄像头实时视频；
2. 实时语音对讲和机器人主动呼叫；
3. 通用文件上传、存储、处理、下载和播放；
4. 控制会话、设备动作和多合一喊话设备；
5. 大屏设备、地图、任务、告警聚合与实时事件；
6. 大屏统计结构和 PDF 报告。

本文档的“已实现”指代码已有路径，不等于已在所有真实设备和生产网络上验收。RTSP、音频设备、LiveKit、MinIO、EMQX、Management 等外部依赖必须以目标环境证据确认。

## 2. 系统边界

| 模块 | 需求边界 |
| --- | --- |
| Bigscreen BFF | 作为生产统一入口验证 JWT，代理/聚合下游数据，桥接 Control WebSocket |
| Control Service | 管理设备运行时状态、排他控制租约、视频编排、设备动作和 MQTT |
| Media Service | 管理视频会话、LiveKit、对讲占用、录像、文件、HLS 和 TTS |
| Management Service | 权威提供机器人、设备能力、固定摄像头、地图和任务等业务档案 |
| 机器人客户端 | 执行 MQTT 命令，适配 RTSP、LiveKit、音频及厂商设备，上报状态 |
| 固定摄像头 Gateway | 按固定摄像头命令拉取 RTSP，发布 LiveKit Track，上报会话状态 |
| 前端 | 调用 BFF/Control，使用 Token 直接连接 LiveKit，不直接接触 RTSP 凭据 |

生产中 Control 和 Media 信任 BFF 注入的用户 Header，不得将其直接暴露到不可信网络。

## 3. 总体业务流程

### 3.1 实时视频

1. 用户选择机器人摄像头或固定摄像头。
2. Control 校验设备上下文，调用 Media 创建或复用会话。
3. 新会话由 Media 确保 Room 存在、签发 publisher/viewer Token，Control 发布 MQTT start。
4. 设备端/Gateway 探测 RTSP，向 LiveKit 发布 Track 并上报 status。
5. Control 把 status 转发给 Media，浏览器直接订阅 LiveKit Track。
6. 最后 viewer 离开后会话延时释放，对讲占用可独立保持 Room。

### 3.2 控制与设备状态

1. 前端获取控制画像；动作优先来自 Management 登记能力，没有可识别映射时可能来自当前生产兼容动作表。
2. 对需要排他控制的装备申请 30 秒租约，同一终端可续期。
3. Control 校验机器人、设备、action、租约及参数范围，再发布到对应 MQTT Topic。
4. 机器人客户端上报设备真实运行态，Control 合并档案后广播 `robot.state`。

### 3.3 文件与报告

1. 小文件通过 multipart 单请求上传，大文件通过预签名 URL 分片直传 MinIO。
2. 视频完成后由 ffprobe/ffmpeg 生成 fMP4 HLS，非视频文件通常直接进入 `READY`。
3. 前端抓拍是对 LiveKit Track 截帧后上传普通 `IMAGE`，不创建后端抓拍任务。
4. BFF 统计报告在 `POST /reports/export` 请求内同步生成并下载 PDF，同时写入本地报告历史。

## 4. 功能需求

### 4.1 实时视频

#### REQ-VIDEO-001 创建、复用与观看

- 系统应按 `sourceType + sourceId + deviceId + channel + quality` 复用有效会话。
- 每个 `userId + clientId` 作为独立 viewer，同一会话多人观看不重复启动 publisher。
- viewer Token 只允许访问指定 Room；具备 `MEDIA_OPERATOR` 的交互 viewer 可发布麦克风。
- 验证：从 `INIT -> REQUESTING_CLIENT -> ROOM_READY -> STREAMING` 完成闭环，浏览器只订阅目标 Track。

#### REQ-VIDEO-002 心跳、停止与释放

- viewer 应周期心跳；超时或显式 stop 只移除当前 viewer。
- 最后 viewer 离开且无对讲占用时进入 `IDLE_WAIT`，延时后删除 Room 并停止对应 `sessionId` publisher。
- 验证：一个浏览器离开不影响其他 viewer，一路释放不影响其他会话。

#### REQ-VIDEO-003 切换、重启与恢复

- 机器人摄像头支持 `visible/thermal/fusion` 枚举与 `sub/main/auto` 枚举，实际可用性由设备源决定。
- 中断会话应能按宽限时间恢复；机器人 offline -> online 时应恢复仍有 viewer 的会话。
- 验证：新 publisher Token、新 commandId、会话字段和最终 Track 一致。

#### REQ-VIDEO-004 固定摄像头

- 固定摄像头在 BFF `devices[]` 中与机器人同级，但不显示机器人控制入口。
- 启动时必须校验 Management `enabled` 和码流，只使用 `visible`，主/子码流缺失时可回退。
- 单路和批量启动均应返回可定位到 `cameraId` 的成功/失败结果。
- 验证：Gateway 能探测 RTSP、发布 Track、上报状态并按 session 释放。

### 4.2 对讲与主动呼叫

#### REQ-ICM-001 视频会话对讲

- 对讲可复用已有 Room，也可以创建不计 viewer 的音频容器会话。
- 机器人、操作员和浏览器 client 任一维度不得同时占用其他对讲。
- 对讲心跳超时应释放占用并停止机器人音频桥。
- 验证：开启、重签 Token、心跳、关闭和忙线错误皆与独立对讲状态一致。

#### REQ-CALL-001 机器人主动呼叫

- Control 应消费 invite/cancel，向前端广播 incoming/status，并允许通过 WebSocket accept/reject/query。
- 接听需要 `MEDIA_OPERATOR`，成功后创建对讲，状态同步回传机器人。
- 验证：重复来电、忙线、拒接、取消、超时和对讲结束均进入明确状态。

### 4.3 通用文件

#### REQ-FILE-001 简单上传与文件归属

- 简单上传应接收文件、`fileType`、机器人/设备关联、扩展 ID、源文件 ID 和 metadata。
- 应校验文件名、大小、扩展名和内容类型，生成服务端统一对象路径。
- 验证：非视频成功后可查询和下载，文件归属不能跨组织误用。

#### REQ-FILE-002 multipart 直传与恢复

- 创建接口应支持基于源文件标识恢复未过期上传，返回已上传 part 和待上传 URL。
- 客户端 PUT 分片到对象存储，complete 时服务端校验 part 数量和大小。
- 过期、失败或删除时由服务端中止对象存储 multipart；当前无独立 cancel API。
- 验证：断网重试不重传已完成 part，完成后对象大小和文件状态正确。

#### REQ-FILE-003 处理、播放与删除

- 视频文件应进入 HLS 处理，处理任务使用租约防止重复领取。
- 下载和播放 URL 应有期限；HLS 资产必须验证播放 Token。
- 单个和批量删除均应清理原文件、HLS 和上传会话，批量删除逐条返回结果。
- 验证：`READY/PROCESSING/FAILED/DELETED` 等状态、错误和对象资产一致。

### 4.4 统一控制与多合一设备

#### REQ-CTRL-001 控制画像和排他租约

- 控制画像应合并 Management 档案/能力与 Control 运行时状态。
- 租约冲突以同一机器人且 `deviceIds` 交集非空为准；同一终端重复申请应续期。
- `drive.velocity` 必须要求在线、手动模式和当前终端持有 `base`。
- 验证：冲突返回占用人信息，有效移动指令续期租约，释放后可重新获取。

#### REQ-CTRL-002 设备动作与状态

- 对外 action 优先由 Management `components[].capabilities[].actions` 映射；当前已知设备类型在没有可识别映射时使用生产兼容动作表，新增能力不得继续扩充隐式兜底。
- Control 应按设备类型构造参数并路由到 body、ptz、audio、launcher、net-gun、warning-light、vehicle-light 或 multi-function Topic。
- 发布成功只代表 MQTT publish 成功，当前不等待设备 ACK；设备真实态以后续上报为准。
- 验证：不在控制画像最终 `devices[].actions` 内的 action、越界参数和不满足安全条件的请求被拒绝；兼容动作不得生成虚假运行状态。

#### REQ-CTRL-003 多合一喊话设备

- 应支持音量、实时广播/监听、文本 TTS、音频文件、警报、灯光和扬声器/灯光俯仰动作。
- 实时广播/监听必须传 `mediaSessionId`；音量、TTS、灯光和俯仰必须按 `controlProfile` 校验。
- 音频文件必须为同一机器人/设备的 `AUDIO + READY`，小于等于 20MB 且扩展名为 `.mp3/.wav`；传输需 `EQUIPMENT_OPERATOR`。
- Media OpenTTS WebSocket 生成与多合一 `play_tts` 是两条不同链路，需求和验收不得混用。
- 验证：每个已登记动作的 MQTT 载荷与客户端驱动约定一致，真实设备可以返回可观测状态。

### 4.5 大屏 BFF

#### REQ-BFF-001 认证、代理与数据聚合

- BFF 应验证 JWT issuer、签名算法及 client audience/azp，覆盖调用方伪造的用户 Header。
- 应提供全景 overview、设备详情、任务、告警和告警处置，並严格限制业务代理白名单。
- 未取得权威数据的字段返回 `null`/空数组或明确失败，不生成普遍适用的业务假数据。
- 验证：下游错误状态和正文保持，敏感 RTSP 和凭据不进入前端模型。

#### REQ-BFF-002 WebSocket 事件

- BFF 应为每个浏览器连接建立 Control WebSocket 上游，原样桥接消息并适配 `panorama.*`。
- 任务失效通知应去抖后重查权威任务，统计应在相关变化后去抖重查并只推差异。
- 验证：上游不可用时不伪造动态业务事件；重连后前端能通过 REST 重建全量状态。

#### REQ-STAT-001 统计与 PDF 报告

- 统计总览应保留筛选条件和结构；未接入权威统计源的业务值使用 `null`/空集合。
- 报告 export 应同步返回 PDF 并记录本地历史，支持列表、下载和删除。
- 验证：PDF 可打开，历史与本地文件一致，删除后返回 `204`。

## 5. 已知差距与扩展边界

| 编号 | 当前差距 | 上线/验收条件 |
| --- | --- | --- |
| GAP-AUTH-001 | Media 活跃会话、按 ID 查询和 Track 当前缺少组织/用户过滤 | 多租户生产前补齐服务间身份和资源授权 |
| GAP-VIDEO-001 | Media 不消费 LiveKit Webhook，Track 状态依赖 MQTT status | 明确状态权威源，补充差异检测或接受风险 |
| GAP-WS-001 | Control 未将 Media `video.*` 广播转发到 BFF WebSocket | 前端以 LiveKit/REST 为准，或补齐事件桥接 |
| GAP-FIXED-001 | 代码已完成 Gateway 心跳、RTSP 健康、配置状态和会话状态分离；多 Control 实例共享状态尚属部署边界 | 单实例代码闭环；生产验收需验证断开恢复、过期和多实例一致性，不得把 `enabled` 作为在线证据 |
| GAP-SEC-001 | Control 与固定摄像头 Gateway 敏感日志 | 代码脱敏已完成；历史日志治理和部署后采样待执行，MQTT TLS/ACL 按独立风险验收 |
| GAP-BFF-001 | `test111/SN005/SN006` 无定位时仍有演示位置事件 | 生产移除/配置化，验收不得视为真实定位 |
| GAP-STAT-001 | 统计业务值尚未接入权威统计源 | 如交付真实指标，需先定义来源、口径和时区 |

统一控制二期的机械臂轨迹、点云、多厂商驱动插件、完整任务接管/恢复和命令历史回放仍是扩展范围，不得因为一期存在通用 action 就判定为已实现。

## 6. 核心数据对象

| 对象 | 关键语义 |
| --- | --- |
| 视频会话 | 视频源、设备、通道、清晰度、Room、Track、viewer、状态与错误 |
| 对讲占用 | 独立对讲状态、操作员、client、心跳和机器人音频 Track |
| 主动呼叫 | 呼叫 ID、机器人、状态、到期时间、接听人和媒体会话 |
| 文件 | 组织/机器人/设备归属、类型、源文件标识、对象路径、上传/处理状态和播放资产 |
| 控制会话 | 机器人、用户、client、设备范围、租约与占用人 |
| 控制命令 | 目标设备、action、params、client seq、commandId 和发布结果 |
| 大屏设备 | 机器人/固定摄像头统一识别、状态、位置、类型、任务与播放属性 |
| 报告 | 报告 ID、筛选条件、PDF 路径、文件大小和生成时间 |
